# 分数、不确定性与反过拟合

[四条学习路线与术语](../00-从这里开始.md) · [本 Track 入口](01-为什么这个比赛不能靠反复改Prompt试分.md)

一个有效高分是真实成果，但选择方案还需要知道它对什么问题有效。先把高低样本放在一起，检查样本单位和比较条件，再讨论怎样避免把本地轨迹、幸运结果或局后知识写成普遍规则。

## 按问题跳读

## 分数能支持多大的结论

题目中的“几乎”并不否定真实高分。一条有效样本能够证明固定身份在某次轨迹上得到这个结果。它不能独自回答平均表现、稳定性、因果收益和隐藏测试迁移，而最终选择往往需要考虑这些问题。

### 先同时摆出所有关键样本

**事实：** 以下成绩来自 [最终证据审查](../../project/FINAL_EVIDENCE_REVIEW.md) 和具体运行记录，保留原口径。

| Candidate | quantitative | survival / grade / Level | 证据限制 |
|---|---:|---|---|
| v1 高样本 | 76.04 | 48m / A / L6 | Tier-B 历史摘要，raw 不可得 |
| v1 低样本 | 35.31 | 25m / D / L4 | 与高样本同来源 pair，身份不完整 |
| exact-v6 | 75.29 | 48m / A / L6 | 一个被接受的完整样本；adherence FAIL |
| v8a RUN-0004 | 72.65 | 48m / A / L5 | 同冻结身份的样本一 |
| v8a RUN-0002 | 59.00 | 48m / C / L4 | 同冻结身份的样本二 |

同来源 pair 不表示受控实验；同 Candidate 两局也不表示所有条件一致。完整成绩绑定真实轨迹，比较结论仍需要额外条件。

### Sample size：我们到底观察了多少

**Sample Size（样本量）** 是用于回答某问题的有效观测数量。样本单位必须清楚：两个 Run 是两条轨迹，203 个动作不是 203 个独立 Candidate 性能样本。

**解释：** 一个长程 Run 内的动作相互影响。早期资源和机会会影响后续，不能把每月记录拆成大量独立样本，再宣称统计证据充足。

对 exact-v6，只有一个完整样本。75.29 是这个样本的分数，不是 expected score（期望分数）。即使这是该候选唯一可用值，也不能把“唯一值”解释成“稳定值”。

对 v8a，两条结果证明至少发生过两种不同结果；仍不足以知道典型表现、低端概率或高分概率。读者可以计算描述性差异，但任何计算都不能创造新的独立观测。

### 为什么 75.29 < 76.04 不证明 v6 更差

“更差”需要定义比较目标。是最大观测值、稳定完成、常见分数、低端风险，还是部署可审查性？不同目标需要不同证据。

**事实：** v1 的 76.04 是更高的历史单次记录，但同候选有 35.31 的另一条历史结果，raw 不可得，完整身份不充分。Main 没有把它作为稳定分布或最终包身份。[最终方案审阅](../../project/FINAL_SOLUTION_REVIEW.md)

**解释：** 若目标只是列“已有记录里的最大数字”，76.04 确实应显示在前面；若目标是选一份可冻结的成熟工程方案，则还要考虑身份、架构与证据完整性。两种问题不应该用同一张排行榜替代。

同样，不能反向把 v1 的低分当成“v6 一定更稳定”。v6 没有重复完整样本，稳定性仍未知。

### 为什么 72.65 > 59.00 不证明代码变差

**事实：** v8a 两个样本保持同一冻结行为身份。样本一和二的轨迹、等级和输出格式有差异，但不是两份不同 Candidate。[样本一](../../project/runs/v8a-full-horizon-sample1.md) · [样本二](../../project/runs/v8a-full-horizon-sample2.md)

**解释：** 模型每次执行可以产生不同文本与决策，环境机会也会不同。因此“输出格式变了”不一定有对应文件修改；“分数下降”不一定是回归代码。

研究应先检查版本与加载身份是否真的相同，再检查轨迹和执行差异。身份相同减少了一个解释，却没有自动证明剩余差异全部来自某一种随机源。

### Selection bias：试得越多，最高值越容易误导

**Selection Bias（选择偏差）** 在反复试分中尤其常见。如果每次只保留最好结果，最后的最大值同时反映方案能力和尝试机会。试过更多次的路线有更多机会遇到高结果。

**教学示例：** 两个团队都使用同一方案，一个展示全部两次结果，另一个从许多尝试中只展示最好一次。即使第二个公开分数更高，也不能据此说它采用了更强方案。这里没有给项目增添未记录的尝试次数。

报告所有授权样本、保留低分与技术失败，可以让审查者看到选择过程。它仍不能消除全部混杂，但能减少信息被挑选的程度。

### Technical contamination：成绩之外还有执行过程

**Technical Contamination（技术污染）** 指运行故障、身份错配或协议偏离影响了比较意义。它和自然轨迹差异需要分别说明。

**事实：** v7i 历史故障产生 stale score（过期分数）归因风险；v7m 在 M20 技术退出，没有终局成绩；v6 有有效分数同时存在协议偏离。这三种情况不能统一标成“策略失败”。[Provider 取证](../../project/reviews/S07-39_PROVIDER_CONNECTIVITY_FORENSICS.md) · [v7m 取证](../../project/reviews/S07-47_V7M_M20_PARTIAL_RUN_FORENSIC_REVIEW.md) · [v6 记录](../../project/runs/v6-run1-validation.md)

有效分数也不自动适合所有比较。若研究某个 recovery（恢复）规则，而运行并未遵循它，就不能用结果证明“该规则提高了分数”。

### 什么叫描述性、方向性、因果性

| 结论类型 | 可以怎样说 | 需要防止什么 |
|---|---|---|
| Descriptive（描述性） | 这次记录为 75.29，完成 48m | 把单次值当期望 |
| Directional（方向性） | 某些窗口提供值得继续核验的机制线索 | 把线索当收益确认 |
| Inconclusive（无法定论） | 当前记录不能区分几个解释 | 为叙事强行选根因 |
| Causal（因果性） | 改动导致收益，需要能排除其他解释 | 仅凭相关性或历史分差下结论 |

**解释：** 这是教学用语，不是项目新设的统计分级。本项目许多比较属于 small-N（小样本）、historical（历史）与 confounded（混杂）比较，不能包装成严格统计试验。

没有可支持的统计设计和足够数据时，不应使用 statistically significant（统计显著）、stable distribution（稳定分布）或 causally proven（因果已证明）描述结果。

### 生存、晋升与分数不能相互填补

**事实：** v8a 两次都完成 48m，但分别到 L5 与 L4；v1 低样本在 25m 终止却为 L4；v6 完成 48m 到 L6。这些字段在 canonical 记录里分别保存。[最终证据审查](../../project/FINAL_EVIDENCE_REVIEW.md)

**解释：** 完成率描述样本是否达到时程边界，Level 描述终局等级，分数描述特定评分口径。不能因为都存活就说表现相同，也不能因为等级相同就推断相同分数。

工程决策可能同时关心高位表现和低端风险，但必须明确这些是选择考虑。一个小样本组合不足以给各风险赋可靠概率，不能制造“综合期望效用最佳”的新事实。

### 为什么不能从少数样本补出概率

**教学示例：** “两个 Run 都完成”可描述为“这两个已观察 Run 完成”；写成“未来完成概率 100%”则把观察频数当成未知环境的真实概率。这里的两个 Run 不代表完整可能轨迹。

在项目里，v8a 的两次完成保留为样本事实，没有给出总体稳定分布。exact-v6 的一次完整更不能排除自然低端结果，也不能排除技术失败。

**解释：** small-N 不意味着不能做任何判断。它意味着选择时要使用更窄的语言：固定身份、已观察上界、已知限制和未知重复性。决策可以明确，证据不能被写大。

### 能不能只拿“相似月份”来比较

相同月份、Level 或 Review 结果会减少某些差异，但它们未必有相同 tenure、资源、可选机会和历史负担。长程系统还保留前序选择的影响。

**事实：** 策略挖掘发现相近窗口仍有多种混杂，收紧匹配又会使本已很小的样本减少；报告没有因此声明 matched causal gain（匹配因果收益）。[策略挖掘](../../project/research/S10-21_REVIEW_WINDOW_STRATEGY_MINING.md)

**解释：** 描述性对照可以帮助提出机制假设，不能因表格行看起来相似，就称为严格控制。保留相似与不同条件，比强迫结论明确更可靠。

### 报告分数时的实用纪律

同时显示 Candidate 身份、样本数、完整/部分状态、quantitative 与 partial 字段、survival 月数、adherence 和来源级别。低分样本放在同一视野里，unknown 不填零。

**教学示例：** 将“v6 得分 75.29，策略最佳”改写为“exact-v6 一个完整样本为 75.29，运行遵循失败；Main 在成熟三 Skill 路线中选择其历史身份，稳定性与最优性未证明”。后一句更长，但复核者能知道它实际支持什么。

这一纪律不是拒绝决策。工程必须在有限证据下做选择；第 11 章会解释怎样选择，同时保持未知。

小样本让比较保持不确定；如果继续只围绕已见结果修改规则，还可能把这种不确定转成过拟合。下面检查决策输入、探索与确认的边界，而不替隐藏测试补结论。

## 如何避免过度适应已知结果

**Overfitting（过拟合）** 在 Agent 竞赛中，不只指机器学习参数记住训练数据。它也可能是研发规则过度适应某些本地轨迹、一次幸运运行或局后已知事件，无法推广到未见机会与风险。

**Anti-overfit（抗过拟合）** 是降低这种适应偏差的做法。它不能凭自身证明 hidden-test transfer（隐藏测试迁移）成功；迁移仍需相应来源与评测证据。

### 四种容易忽略的适应

#### 适应 local trajectories（本地轨迹）

反复研究几条熟悉轨迹，会让我们把某种机会顺序当成环境规律。规则在这些轨迹上合理，遇到新菜单或不同资源时却可能不适用。

**事实：** S10-21 的历史窗口在机会、tenure、Level、资源与历史风险上混杂，没有产生安全部署的普遍策略增量。[策略挖掘](../../project/research/S10-21_REVIEW_WINDOW_STRATEGY_MINING.md)

**解释：** 不能把“在这几局里常见”写成“所有局都应这样做”。可迁移假设应依赖当时可观察机制，如当前警告或新反馈，而不是已知轨迹名称。

#### 适应 one lucky run（一次幸运运行）

只保留最大值会把特殊轨迹当成能力分布。v1 的 pair 与 v8a 的 pair 是提醒：相同候选可以有不同结果。

前面的样本表已把高低结果放在一起；使用这些材料时应保留配对与来源限制，避免在展示中再次只选择高值。

保留 pair 不等于已经建立统计控制，也不等于观测差异完全是随机性。它首先让不确定性可见。

#### 适应 known events（已知事件）

逐事件添加答案规则，可能形成 event-answer mapping（事件答案映射）。当这些规则来自隐藏资料或未来结果时，还会越过参赛信息边界。

**事实：** 项目冻结公共事实、当前 session 与新鲜观察边界，不允许把隐藏阈值和 Test 数据用作策略知识。[官方来源锁](../../project/OFFICIAL_SOURCE_LOCK.md) · [运行合同](../../project/AGENT_RUNTIME_CONTRACT.md)

**解释：** “根据公开文本拒绝明显欺骗”与“知道某标题必须选编号 2”是不同依据。前者是一般公开语义规则，后者需要问它来自哪里、能否合法部署和是否对未知菜单成立。

#### 适应 forensic hindsight（取证后的已知结果）

局后能看到完整路径，读者会觉得正确动作显而易见。但实际决策时没有未来反馈，部分隐藏信息也不能使用。

**解释：** 分析者应重建 decision-time information set（决策时信息集合），只用当时公开状态提出可部署假设。不能把后来死亡当成当时必然知道的风险强度。

### Public evidence firewall：把决策输入边界写清楚

**Evidence Firewall（证据隔离边界）** 区分分析端可见材料和策略端允许输入。它不仅限制隐藏数字，也限制 session 身份、未来分数和诊断字段进入策略。

**事实：** S10-22 的 evaluator 保存最终 reward（奖励/成绩），policy process（策略进程）只接收白名单公开字段。研究还发现普通 MCP serialization（序列化）中的 choices 可能包含 status_updates，任务使用更严格白名单将整张映射剔除。[Simulator 研究](../../project/research/S10-22_SIMULATOR_POLICY_SEARCH.md)

这说明“经过官方接口”不自动满足某个研究自设的更严格边界。输入规则需要明确，而不能只相信字段名字。

**解释：** Firewall 让读者能追问每个特征的来源。它没有证明研究不存在任何过拟合，也不能把 public-only 直接当成隐藏测试效果。

### 项目已经采用的抗误判做法

| 做法 | 本项目依据 | 能改善什么 | 仍不能证明什么 |
|---|---|---|---|
| 高低样本同时展示 | v1 / v8a pair | 避免只保存最好一次 | 稳定分布 |
| 保留技术部分局 | v7m | 暴露执行与样本筛选问题 | 终局成绩 |
| 区分完成与遵循 | v6 | 防止高分遮住合同缺陷 | 改规则的因果收益 |
| 只使用 participant-visible 输入 | Runtime Contract、Simulator | 限制隐藏证据混入 | Hidden transfer |
| 有界 Candidate 比较 | 架构决策与评估合同 | 限制事后无限试分 | 全局搜索最优 |
| 门禁失败停止 | Reviewer / Simulator | 避免无效或不安全扩张 | 该机制普遍无用 |

**事实：** 这些做法与边界见 [实验复盘](../../project/EXPERIMENT_RETROSPECTIVE.md)、[Candidate 合同](../../project/CANDIDATE_EVALUATION_CONTRACT.md) 和 [架构决策](../../project/ARCHITECTURE_DECISIONS.md)。表的组织方式属于教学解释。

### Holdout 与 hidden Test 是不同对象

**Holdout（留出验证）** 是计划保留用于后续检验的材料或样本，避免在同一部分数据上持续调规则。它的价值依赖是否真正留出、是否独立于选择过程、是否代表目标环境。

**事实：** Controller 有 12 Dev +12 holdout 回放案例，但它没有正式 gameplay 效果证据。Simulator 计划的 128-seed holdout 未运行，因此不能说在该留出集上验证或失败。[Controller](../../project/research/S10-20_PROMOTION_WINDOW_CONTROLLER.md) · [Simulator](../../project/research/S10-22_SIMULATOR_POLICY_SEARCH.md)

**解释：** 同样叫 holdout，可能是人工历史案例，也可能是未来随机种子。它们不等同于比赛官方隐藏环境。保留名称并不能跨越验证对象差异。

### Hidden Test 仍然 UNKNOWN

**事实：** 官方上传 = NOT PERFORMED / NOT PROVEN；platform score = UNKNOWN；hidden-test transfer = UNKNOWN。[最终方案审阅](../../project/FINAL_SOLUTION_REVIEW.md)

**解释：** 本地 Dev 适合检查工程、形成机制假设和描述已观察表现；隐藏评测回答未见条件中的表现。二者之间需要新证据，不能由一份漂亮复盘代替。

要避免两种极端：既不能把本地 75.29写成官方成绩，也不能因为没有隐藏结果就否定已有工程成果。实际完成的控制循环、身份审计和负结果管理仍有价值，只是其性能外推有边界。

### 为什么不把局后低分解释全部写进 Prompt

局后解释常常有许多 plausible（合理但未证实）叙述：某次成长投入太少、某警告维护太久、某机会没有争取。若每条都变成“必须”，规则会堆积互相冲突的优先级。

**事实：** 项目后期挖掘没有安全新策略 delta，Controller 也没有证明修正多个主要决策错误。[策略挖掘](../../project/research/S10-21_REVIEW_WINDOW_STRATEGY_MINING.md) · [Controller](../../project/research/S10-20_PROMOTION_WINDOW_CONTROLLER.md)

**解释：** 更合适的产物可能是一个有范围的假设，附上反例与未知。例如“检查当前公开警告是否仍约束机会”，比“曾出现警告就永远优先清理”保留了机制判断。前者也仍需要未来授权验证。

抗过拟合不是完全不学习历史；它要求从历史中学可观察机制，并检查它是否依赖已知结局。只按事件标题或终局结果添加规则，容易让过去越解释越好、未来越不确定。

### 保留未知如何改善展示与沟通

如果写“Hidden Test UNKNOWN”，读者能区分本地研发成果和平台结果；如果只写“已冻结最终包”，读者可能误以为已经上传并评测。

**解释：** Unknown 应与对象绑定：上传状态未知、平台分数未知、迁移未知是三个判断。没有平台成绩不意味着本地包身份未知；没有 v1 raw 不意味着其历史摘要必须被删除。

这一习惯可以迁移到普通 Agent 产品。成功演示、生产上线、真实用户收益和长期可靠性分别需要证据。准确标注未知，让下一步工作能对准缺口，而不是继续强化已经通过的部分。

### 怎样在不确定时继续决策

**教学示例：** 新规则只解决一个已经见过的事件。先写成 HYPOTHESIS，并检查它是否依赖事件名称、未来结果或隐藏字段；再问它能否转成公开机制描述。没有授权新实验时，只记录假设，不把它补进冻结提交。

**解释：** Anti-overfit 的核心习惯是：保留反例，限制输入，把探索与确认区分，停止不能增加信息的路径。它是本项目支持的研究纪律，不是取得隐藏高分的保证。
