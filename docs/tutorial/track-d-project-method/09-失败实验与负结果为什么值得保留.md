# 09｜失败实验与负结果为什么值得保留

**Negative Result（负结果）** 是研究没有支持预期判断时留下的结果。它可以缩小搜索范围、阻止不安全部署、揭示比较方法的问题。前提是准确描述“哪件事没有得到支持”。

**INTERPRETATION｜解释：** “失败”若没有对象，会把未测量、技术故障、低分和可行性门禁混为一谈。下一位开发者可能因此重复无信息工作，或者错误关闭有价值方向。

## 六种标签有不同含义

| 类型 | 实际判断 | 真实项目例子 | 不能推出 |
|---|---|---|---|
| Unsupported improvement（未支持改进） | 没有足够证据确认收益 | 后期加固未形成稳定 75+ 突破 | 所有改动无价值 |
| Technical failure（技术失败） | 执行链在可比较结果前中断 | v7m M20 部分局 | 该 Candidate 会自然死亡 |
| Feasibility failure（可行性失败） | 后续研究必要前提不成立 | Simulator 基础胜任门禁失败 | 宏策略比较已失败 |
| Weak signal（弱信号） | 有观察，但不足以支持部署 | Controller / strategy mining | 方法逻辑完全无用 |
| Inconclusive（无法定论） | 不能区分关键解释 | v7m 连接根因 | 猜测的根因已成立 |
| Not tested（未测试） | 尚未执行相应研究 | Team / Swarm | 已测试而失败 |

**FACT｜事实：** 表中路线与结论分别见 [实验复盘](../../project/EXPERIMENT_RETROSPECTIVE.md)、[v7m 取证](../../project/reviews/S07-47_V7M_M20_PARTIAL_RUN_FORENSIC_REVIEW.md)、[Simulator](../../project/research/S10-22_SIMULATOR_POLICY_SEARCH.md)、[Controller](../../project/research/S10-20_PROMOTION_WINDOW_CONTROLLER.md)。

这些是教学分类，不是一个所有项目通用、按优劣排列的结果等级。

## 为什么 Provider 错误不是策略失败

**FACT｜事实：** v7i 的历史 Provider 异常发生在有效 HTTP 响应之前，且输出存在旧成绩风险。没有新局轨迹与正确分数绑定，不能用该报告评价策略。[Provider 取证](../../project/reviews/S07-39_PROVIDER_CONNECTIVITY_FORENSICS.md)

**INTERPRETATION｜解释：** 这类失败首先告诉你“本次运行没提供合格策略样本”。它仍然提供部署可靠性与归因风险信息。把它记成零分会制造一个未发生的游戏 outcome（结果）；把它静默删掉又会隐藏工程不可靠性。

MCP（模型上下文协议）注册失败也需要相同思路。注册/发现门禁失败时，尚未观察正式 Agent 的动作策略；不能说风险 Skill 已被游戏证明无效。项目早期加载与应用需要分开举证的合同，正是为了避免这种跳跃。[运行合同](../../project/AGENT_RUNTIME_CONTRACT.md)

## Schema rejection：拒绝发生在什么边界

**FACT｜事实：** v6 的一次 Energy 多选参数在状态改变前被拒绝；202 次成功动作仍有各自新观察。拒绝是格式/执行缺陷，不能把它统计成一个成功游戏动作。[v6 运行记录](../../project/runs/v6-run1-validation.md)

**INTERPRETATION｜解释：** 同样的最终低分，可以来自策略选择、参数拒绝、缺观察或机会差异。研究一个 Skill 的收益时，应知道该 Skill 实际有没有被使用，以及错误是否发生在它负责的边界。

## 自然低分不能自动变成技术失败

**FACT｜事实：** v7q 记录 26.80 /18.76/24m/E/L1，属于自然 M24 终局；它与 v7m 没有最终成绩的技术部分局不同。[运行历史](../../project/RUN_HISTORY.md) · [最终证据审查](../../project/FINAL_EVIDENCE_REVIEW.md)

**INTERPRETATION｜解释：** 如果只接受高分为“有效”，低分都被改成“异常”，选择偏差会被流程制度化。自然低分可以提示策略风险，但不能单凭终局结果定位某一句规则为根因。

## Weak signal 为什么仍有价值

**FACT｜事实：** Controller 的 24 个 replay cases（回放案例）中仅一个 state-level correction（状态层修正），有 8 个 UNKNOWN；工具状态持续性工作，并未形成多个关键决策被修正的证据。研究停止创建 v15。[Controller 报告](../../project/research/S10-20_PROMOTION_WINDOW_CONTROLLER.md)

**INTERPRETATION｜解释：** 这告诉研发者：机械记忆可以实现，但如何识别当前警告、实际交付与可实现机会，仍是语义难点。结果对问题定位有用，即使不足以支持部署。

若报告只写“Controller failed”，下一次可能再次制造更复杂存储；如果报告写清“存储可用、语义排序信号弱”，下一次研究可以瞄准真实缺口。

## No deployment 不等于 idea worthless

**FACT｜事实：** Helper 得到 DETERMINISTIC_HELPER_CHALLENGER_SUPPORTED，但仅有 isolated tool-level（隔离工具层）证据，没有正式 Candidate 部署。Reviewer / Memory 则在各自冻结路径前提上停止。[Helper 审计](../../project/research/S10-19R3_NATIVE_CONTROL_SURFACE_AUDIT.md) · [Reviewer](../../project/research/S10-19R1_SUBAGENT_FEASIBILITY.md) · [Memory](../../project/research/S10-19R2_MEMORY_FEASIBILITY.md)

把这些路线全归为“失败”，会把支持信号和部署门禁失败合并。研究组合中可以同时存在：值得继续但尚未部署、当前路径不可行、逻辑信号不足和未测试。

## 失败记录应保存什么

**INTERPRETATION｜解释：** 长期值得保留的是问题、身份、实际门禁、证据、决策与非结论。执行细节若只是可重建临时物，可以另行评估；不可恢复的 raw、未决依赖和 hold 不能因为报告完成就删除。

失败报告还应记录 conditional phases（条件阶段）是否运行。Reviewer 的 Phase B/C 未运行，不能写成审查建议全部无效；Simulator 的 holdout 未运行，不能宣称在未见种子上失败。

记录技术失败可以减少 sample-selection bias（样本选择偏差），但不要求把它与自然终局算进同一成绩平均值。关键是分类可见，而不是强行统一。

## 为什么“没测量”不能记成零

**FACT｜事实：** Reviewer 没有进入真实建议阶段，所以 latency、token 与成功率是 NOT_MEASURED；零 reviewer invocations（调用）是执行次数，不是一次 reviewer 实测耗时为零。[Reviewer 研究](../../project/research/S10-19R1_SUBAGENT_FEASIBILITY.md)

**INTERPRETATION｜解释：** “0 次运行”“没有分数”“分数 0”分别描述计数、缺失和数值。混用会污染后续统计与路线选择。没有记 usage（用量）时也不能写零成本。

这种纪律适用于所有 Agent 工程。一个任务被门禁阻断，不能报告该能力的实际成功率；一个服务请求没有响应，不能凭缺失计费字段猜测收费为零。

## 负结果怎样影响下一次授权

一条负结果应改变后续问题，而不是只增加重试理由。部署前提失败需要新的安全路径证据；语义排序信号弱需要更强的案例或机制；底层连接原因未知需要有界诊断，不能立即改 Prompt。

**INTERPRETATION｜解释：** 重新打开路线应指出新 material evidence，说明它为何改变原门禁。单纯“再试一次可能成功”没有解释旧证据。另一方面，换了路径或前提后，也不能沿用原负结论称新设计必然失败。

**TEACHING EXAMPLE｜教学示例：** 如果未来有机械隔离的新 reviewer loader，原 frozen-path 部署失败仍是正确历史记录；新路径需要独立检查，不能先宣称已被旧研究证实或否定。

## 怎样读一个负结果

先找 decision token（决策标记），再看测试对象与前提。接着检查实际执行阶段、未测量能力和 stop rule（停止规则）。最后问：未来若重新打开路线，需要哪个新的 material evidence（实质证据）？

**TEACHING EXAMPLE｜教学示例：** “Memory 无效”可改写为“冻结路径下指定 automatic MEMORY.md anchor 没有满足自动可用门禁；explicit read 工作，其他记忆设计尚未被否定”。这份结论既能阻止原样重复，又没有关闭所有记忆方向。

项目保存失败，是为了让决策可复核。保存失败知识与永远保留全部过程文件仍是两件事；后续精简需遵循 [Track C 保留原则](../track-c-repository-tooling/12-哪些文件值得长期保留以及哪些最终可以删除.md)，本轮不执行清理。
