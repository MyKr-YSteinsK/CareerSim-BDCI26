# Track D｜学习地图

一份 Agent（智能体）方案改完后，怎样知道它值得采用？这是 Track D 的中心问题。文件正确、工具可用、游戏完成和分数提高，分别回答了不同的问题；把这些判断连起来，才能讨论最终选择。

本教材以 CareerSim 已有证据为例，讲解 Experimental Method（实验方法）。它不要求读者先懂统计学，但要求读者愿意把“我希望它有效”和“记录证明它有效”分开。

## 怎样读“事实”和“解释”

本书保留五种标签：

- **FACT｜事实：** 可以回到指定代码、合同或运行记录核对。
- **HYPOTHESIS｜假设：** 正在或曾经等待验证的判断。假设存在不代表它成立。
- **INTERPRETATION｜解释：** 基于事实组织出的含义、取舍或可迁移经验。
- **TEACHING EXAMPLE｜教学示例：** 用于练习判断的设例，不是新增比赛样本。
- **UNKNOWN｜当前证据不足：** 来源缺失、身份不完整，或记录不能区分多个解释。

**INTERPRETATION｜解释：** 阅读一个结论时，依次问：对象是谁？哪个窗口？用了什么证据？反对解释是什么？仍缺什么？“某次有效”只有加上这些边界，才有可复核的含义。

来源导航以当前 canonical engineering source（权威工程来源）和具体运行/研究记录为准。S11-30 source pack 是作者的导航材料，不是独立事实源。文件中的历史状态按当时语境理解：早期报告写 Stage ACTIVE，与后来 closeout 接受完成，可以同时成立。

## 学完后检查自己

你应该能够解释 Candidate、Run 与 Experiment 的不同，指出高分只证明一次观测；说明 runtime validation（运行时验证）与 adherence（运行遵循）各自检查什么；解释完整 gameplay（对局执行）为什么不能代替协议遵循。

你还应能说明取证和失败记录的价值，理解 anti-overfit（抗过拟合）并不保证 hidden Test（隐藏测试）迁移；同时展示 v1 的两条结果、v8a 的两条结果和 v6 的限制，再解释最终选择。

最后，你应该能够回答 Reviewer、Memory 为什么没有正式采用，Team / Swarm（团队 / 多智能体协作）为什么仍是未测试路线，以及 S01–S11 为什么从“跑起来”逐步转向“可归因、可停止、可冻结”。

**UNKNOWN｜当前证据不足：** S02、S05 的完整独立 Stage 定义，v1 完整 Instruction/raw 身份，以及 HPL 的具体关闭原因，都不会在教材中补造。它们也是学习证据纪律的真实材料。

## 一个贯穿全书的练习

**TEACHING EXAMPLE｜教学示例：** 同事说“测试通过，游戏完成，还拿了高分，所以这个 Skill 已证明能提高成绩”。把这句话拆为至少四个命题，分别标出需要的证据。读完第 04、07、11 章后再回答，你会发现缺失的主要部分是行为身份、全程遵循、重复性和因果归因。

本轮只有文档编写与离线核验，没有新对局、模型调用、安装、DB 查询或 hold 解除。教材里的历史动作是已发生的事实，不授予读者当前执行权限。
