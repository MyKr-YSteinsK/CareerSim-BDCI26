Prompt（提示词）当然可以修改。困难在于：修改后的一局分数，混合了策略、轨迹、模型执行和工具运行的结果。只有一个数字时，很难知道是哪一项发生了变化。

**事实：** CareerSim 项目的目标包含长达 48 个月的状态决策。公开资源、机会、Review（评审）和上下文恢复会持续影响后续动作；项目记录也保留了 provider 连接错误、工具参数拒绝和运行协议偏离。[项目复盘](../../project/PROJECT_RETROSPECTIVE.md)

## 一局分数为什么不能替你解释过程

假设 Agent 在早期事件中选择扩大职责，之后获得一个项目机会。后面的晋升不能只归给新 Prompt 的一句话：最初机会是什么、当时资源是否足够、是否遭遇风险、模型有没有照规则行动，都参与了这条轨迹。

**解释：** Long Horizon（长时程）把早期差异积累到后面。最终分数相同的两局，可以经历不同动作；规则相同的两局，也可以走向不同结果。因此只比较末尾数字，会丢掉研发需要的机制信息。

**Score Variance（分数波动）** 指结果之间的差异。观测到差异，不等于已估计统计方差。本项目样本小、部分原始材料不完整，不能把两条成绩当成已知的稳定分布。

**事实：** v8a 的两个完整样本保持同一冻结行为身份，却分别得到 72.65 和 59.00。这个事实要求我们保留轨迹差异，不足以确定一般情况下的波动概率。[样本一](../../project/runs/v8a-full-horizon-sample1.md) · [样本二](../../project/runs/v8a-full-horizon-sample2.md)

## “高了就留”怎样产生偏差

**Selection Bias（选择偏差）** 是根据结果挑选进入比较的对象。不断改 Prompt，只保留碰巧较高的一局，最后比较的已经不是全部尝试。

**Survivorship Bias（幸存者偏差）** 在本项目中可以表现为只统计走完 48 个月的运行。若把自然早终局删掉，方案的生存边界会消失；若把技术断开的运行无声丢弃，工程可复现性也会被夸大。两种失败需要分开记，但都需要留在研发记录里。

**教学示例：** 甲方案只有一次高分，乙方案同时公开一次较高和一次较低结果。只拿甲的最好一次和乙的低分比较，会奖励信息不完整。这个设例没有新增比赛分数，只演示比较规则怎样改变判断。

**事实：** v1 历史同候选两局为 76.04 与 35.31，后者在 25 个月自然终止；canonical review 要求成对展示，且标明原始证据较弱。不能把 76.04 单独包装成该方案的稳定能力。[最终证据审查](../../project/FINAL_EVIDENCE_REVIEW.md)

## 混杂与执行偏离

**Confounder（混杂因素）** 是同时影响比较、让我们难以单独归因的因素。例如两个方案除了 Prompt，还换了架构、运行合同、恢复规则或机会轨迹。此时分数差不能直接视为 Prompt 的 Causal Effect（因果效应）。

LLM（大语言模型）的实际输出也不是文件文本的复印件。规则可能存在，却没有在全部窗口执行。**Adherence（运行遵循）** 检查的是运行行为是否符合合同：动作格式、观察顺序、恢复重读、风险门和标记是否真的发生。

**事实：** exact-v6 完整样本得到 75.29，并被判定为有效 48 个月完成；同一记录明确为 RUNTIME_ADHERENCE_FAIL。因此，“分数好”不能证明文件中的全部规则已经应用。[v6 运行记录](../../project/runs/v6-run1-validation.md)

技术故障还会制造另一类误导。Provider（模型服务提供方）连接失败可能发生在有效响应之前；工具参数被 schema（数据结构合同）拒绝可能发生在游戏状态改变之前。这时你尚未得到一个能够代表策略表现的终局样本。

**事实：** S07-39 对历史连接异常只能确认响应前失败，底层原因 UNKNOWN。后续当前连通性通过，也没有证明历史原因已找到。[Provider 取证](../../project/reviews/S07-39_PROVIDER_CONNECTIVITY_FORENSICS.md)

## 为什么越解释失败，越可能过拟合

如果知道某局死亡，再回头给那个事件添加专门规则，规则可能只适用于已知事件。更隐蔽的问题是把局后才能看见的内部信息写入 Prompt：它能解释过去，却不一定是参赛者当时可以合法使用的证据。

**解释：** 局后分析应该产生可检查的公开机制假设，例如“当前公开警告没有被保留”，而不是“这一事件答案必须选某个编号”。前者可以在未知菜单和新轨迹中验证，后者容易成为答案记忆。

这并不意味着所有 Prompt 修改都无效。它意味着每次修改应回答一个有限问题：改变什么行为？怎样检查变化实际发生？在什么条件下停下？最终分数只是证据链的一部分。

## 项目为什么停止无界试分

**事实：** S09 的结论是 COMPLETE_WITHOUT_STABLE_75_PLUS_BREAKTHROUGH。S10 转向有界的架构/可行性研究与冻结决策；后来的 strategy mining（策略挖掘）得到 STRATEGY_SIGNAL_WEAK，没有足以安全部署的新策略增量。[实验复盘](../../project/EXPERIMENT_RETROSPECTIVE.md) · [架构决策](../../project/ARCHITECTURE_DECISIONS.md)

**解释：** 当下一次尝试仍然不能区分“策略有效”和“这次轨迹幸运”，继续试分的 information gain（信息增益）可能很低。停止该路径并不否定 Prompt 的价值，而是承认当前比较方式没有给决策提供足够信息。

## 怎样把下一次修改变成实验

先写出观察事实，再提出假设。例如，“某些动作后没有 fresh observe（新鲜观察）”是可核对的问题；“再多写一句提醒就会解决”仍是假设。

然后冻结行为身份和验证窗口，区分静态合同检查、实际执行检查和成绩检查。预先写出遇到技术失败怎么办，哪些结果只能返回审查，哪些结果能支持继续。低分、部分局、未测试路线各自保留标签。

**教学示例：** 将“试试新 Prompt”改写为“检查这一版本是否在每次成功动作后取得同 session 的新观察”。即使完成后分数未提高，仍能回答执行合同问题；如果协议仍失败，也不会用一个幸运分数遮住它。

这就是第 03 章的实验循环。Prompt 在循环里是一种 intervention（干预），不是自动提供因果解释的工具。
