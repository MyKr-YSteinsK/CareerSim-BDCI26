# Track B｜System / Runtime 学习地图

Track A 教你怎样组织一次判断；本路线解释这些规则怎样进入运行系统，怎样通过真实工具改变游戏，以及运行后怎样留下可核查证据。System（系统）是组件的组合，Runtime（运行时）是它们实际执行时的环境与服务。你不需要先会 Python；看到函数名时，先理解输入、步骤、输出和权限。

**FACT｜事实**：本教程基于冻结官方 Runner `f61c738c72e51b77298cc1c14c7c6ebf4b6c527d` 的源码、[官方来源锁](../../project/OFFICIAL_SOURCE_LOCK.md)、[环境记录](../../project/ENVIRONMENT.md)与历史工程证据。它解释历史链路，没有重新安装、启动、访问 DB 或运行游戏。**Current S11 live operations = NOT AUTHORIZED。**

## 1. 从材料到运行，再到证据

```text
官方仓库 / 冻结依赖
→ Python + 虚拟环境
→ solution 材料与校验
→ install 到 JiuwenSwarm 工作区
→ registry（技能注册表）+ IDENTITY（身份文件）
→ AgentServer 与 MCP
→ Runner / WebSocket 驱动
→ 模型 / 工具循环
→ 游戏状态与 session
→ 日志、score、离线审计
→ 有边界的清理
```

上图是概念学习顺序，不是命令执行顺序。比如历史 `play_headless` 提前创建 drive session，带 submission 时先安装并 reload 已运行服务；第六章会按真实源码纠正细节。也不能由“阅读复现步骤”推导当前有执行许可。

## 4. 阅读标记与证据优先级

**FACT｜事实**：源码直接实现，或身份明确的历史记录支持。源码注释描述但本轮未独立验证的框架行为，明确写“源码合同／注释如此定义”。**INTERPRETATION｜解释**：帮助理解职责与失败方式。**TEACHING EXAMPLE｜教学示例**：构造场景，使用“教学示例，不是历史 Run 原始记录。”标记，不假扮历史菜单、会话或日志。

源码回答“这段程序会怎样走”；历史记录回答“那次运行实际发生什么”；两者都不自动回答“今天服务能否连接”。缺少当前证据的内部机制写 UNKNOWN（未知）。真实工具列表只采用已确认注册记录，不为补齐教材发起 live probe（在线探测）。

官方来源锁里的日期、模型映射和门户状态是各自核验时点的事实，本教材不把它们刷新为今天的赛事通知。项目额外脚本、治理和审计也会注明 project-built（项目自建），不能把它们说成官方 Runner 原生功能。

[Track C](../track-c-repository-tooling/00-学习地图.md)解释仓库工具与目录资产；本路线只介绍运行链必需的路径和证据生产，不逐个讲全部 scripts、tests 或本机状态生命周期。[Track D](../track-d-project-method/00-学习地图.md)解释各层验证能支持什么、怎样取证与做决定。B08 讲谁产生记录，C07 讲记录的来源与保留，D08 讲如何据此排除错误归因。

## 6. 入门练习

**TEACHING EXAMPLE｜教学示例，不是历史 Run 原始记录。** 你看到一个 Skill 文件、一个成功 install 回执、一条“我选择 B”的模型文字和旧 output 中的高分。能否说新方案已经执行 B 并得到高分？

参考分析：文件与安装证明材料、复制和元数据；模型文字没有证明工具调用；旧输出还缺当前 session 与配置绑定。缺少执行回执、新观察、终局和来源链，不能把四件事拼成一次成功运行。学会指出这些缺口，就是本路线的起点。
