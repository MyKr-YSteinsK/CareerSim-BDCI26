# 07｜真实案例、反例与失败模式

[学习地图](00-学习地图.md) · [上一章：闭环](06-三Skill协同与一次Action闭环.md) · [下一章：版本设计](08-从版本演化理解Skill设计.md)

本章在[三 Skill 闭环](06-三Skill协同与一次Action闭环.md)之后练习：区分公开事实、候选判断和不能推出的结论。案例入口来自 S11-23 teaching source map（教学来源图）的 E01/E02/E03/E04/E07，并补充同一 v6 权威报告中的晋升、无增益、重开比较与标记关联发现。来源图仅用于定位；精确事实以文内 canonical evidence（权威证据）为准，不复制本机 raw（原始日志）。

**FACT** 是报告直接支持的背景、公开事实和实际行为；每例的“正确决策框架”“能学到什么”是 **INTERPRETATION**。后面的构造练习标 **TEACHING EXAMPLE**。运行审计知道的技术计数、最终成绩和违规发现，不会反过来成为 Agent 当时的动作证据。

## C01｜M6 生存趋势与预算改变：公开变化怎样进入约束

来源：源图 E01；[v6 运行验证](../../project/runs/v6-run1-validation.md)。

**事实背景｜FACT**：M6 公开 Health 6→5→4 伴健康警告，后来恢复至 6、警告清除。

**Agent 当时能看到什么**：同局新观察中的健康值、变化与警告；不能用终局分数或隐藏机制补充风险等级。

**相关规则**：Board 保留公开方向与来源；Planning 用 fresh survival trend 判断候选无关预算；Risk 审具体候选是否直接加重对应约束。

**正确决策框架｜INTERPRETATION**：先确认可比下降与警告，再判断相关预算；不能把每笔小损失切成独立软成本，忽略累计趋势。

**实际发生了什么｜FACT**：文字轨迹使用 TIGHT，恢复与警告解除后后来使用 AVAILABLE。

**事后能学到什么｜INTERPRETATION**：预算不是永久模式，应随公开当前证据改变；缓解行动已提交也不等于警告已解除。

**不能推出什么**：不能设 `Health≤4` 的普遍阈值，不证明某次恢复使最终得分提高，也不证明整局每次预算都正确。

## C02｜M13 RECONSIDER：换候选后还要再 gate

来源：源图 E02；[v6 运行验证](../../project/runs/v6-run1-validation.md)。

**事实背景｜FACT**：一次 M13 健康风险选择发生 genuine RECONSIDER，低负荷合法替代被比较、选择，所选候选再 gate。

**Agent 当时能看到什么**：报告确认的公开健康风险情境与当时合法替代；完整菜单、Gap、所有数值在当前摘要中 UNKNOWN。

**相关规则**：重大风险明确、直接合法缓解项存在、候选未处理三条件；只比一个相关替代，换项重新 gate。

**正确决策框架｜INTERPRETATION**：Risk 触发有限重比；Agent 比目标价值与相关缓解，再审新候选本身，不能以原项 gate 授权新项。

**实际发生了什么｜FACT**：重比与重新 gate 可确认；marker 文本重复，精确控制行配对不能认证。

**事后能学到什么｜INTERPRETATION**：局部行为可以有支持，而整体标记与动作关联仍有缺口；二者分开报告。

**不能推出什么**：不能编原候选整数、G/P/CP/X，也不证明 Risk 标记消除了风险或提高存活率。完整教学推演见[第六章](06-三Skill协同与一次Action闭环.md)，它与真实事实分开。

## C03｜公开晋升与 review reset：旧基线不能自动续期

来源：[v6 运行验证](../../project/runs/v6-run1-validation.md)；源图将同一报告列为主线来源。

**事实背景｜FACT**：晋升发生在 M6、M12、M18、M36、M48，对应 L1→L2→L3→L4→L5→L6。

**Agent 当时能看到什么**：当次新鲜公开晋升／反馈，当前 Level 与公开状态；未来晋升月份在当时不能预先知道。

**相关规则**：实际观察 feedback/promotion/no-advance 后刷新 Board、废弃旧 Progress comparison、新 baseline、一个 Gap，CP 包含 R。

**正确决策框架｜INTERPRETATION**：例如看到 M12 晋升后，旧 Gap 可按新证据保留，但旧 L2 停滞判断不能直接变成 L3 判断；没有结果记录也不能默认未晋升。

**实际发生了什么｜FACT**：review-reset 标记文本出现；确切触发与动作配对含糊，不能认证每个晋升点 reset 都正确。H 的 review 前触发被审计记为 MISSED。

**事后能学到什么｜INTERPRETATION**：反馈结果和复核执行是不同证据；“公开晋升已观察”不能补成“复核合同通过”。

**不能推出什么**：不能把观测月份设为固定晋升表，不把动作先后或某个 Gap 直接当升职原因。

## C04｜Energy 参数拒绝：想做多项，不等于一次工具可接收多项

来源：源图 E03；[v6 运行验证](../../project/runs/v6-run1-validation.md)。**FACT｜事实**：一次 Energy attempt 提交 `choice=6,7,3`，在动作执行前被参数解析拒绝，未改变游戏状态。这组整数是错误输入，不是推荐组合。

**INTERPRETATION｜反例判断**：Planning 想联合考虑多项行动，不等于接口允许一次传多个选择。应按已确认回执判断是否执行；不能将这个已知拒绝推广为“所有超时都无副作用”，也不能把参数错误归成三 Skill 策略失败。接口范围查[提交校验](../track-b-system-runtime/03-Submission、Manifest与Skill校验.md)和[模型到工具再到状态](../track-b-system-runtime/07-从模型决定到Tool调用再到新状态.md)；结果分类查[负结果](../track-d-project-method/09-失败实验与负结果为什么值得保留.md)。

## C05｜两次压缩后未重读：静态身份不能证明恢复遵循

来源：源图 E04；[v6 运行验证](../../project/runs/v6-run1-validation.md)。**FACT｜事实**：开局三份 Skill 读取可确认；两次 CurrentRoundCompressor epoch 后均没有合同要求的三 Skill reread，属于 missed context-recovery rebuild。

**INTERPRETATION｜反例判断**：重读规则与重建当前事实/计划解决不同缺口，启动加载不能覆盖长程恢复要求。记录没有证明某条规则因压缩丢失或因此少得多少分，也不能补造 Agent 当时不可见的宿主信号。恢复条款查[Instruction](02-exact-v6-Instruction逐句拆解.md)，从日志到结论的过程查[Forensics](../track-d-project-method/08-Forensics为什么成为项目的重要部分.md)。

## C06｜M1/M48 无新证据仍重开：推理多不一定更充分

来源：[v6 运行验证](../../project/runs/v6-run1-validation.md)，ordinary-event reconsideration（普通事件重复推敲）段。

**事实背景｜FACT**：普通 Story 决策在没有新公开证据时反复重开比较，报告给出 M1 和 M48 例子。

**Agent 当时能看到什么**：同一组当前公开情境与合法选项；重复生成自己的理由不是新增外部事实。

**相关规则**：普通非战略故事最多两个最强合法候选比较一次；没有 fresh evidence 不重开，除非 Risk 的相关 RECONSIDER 分支。

**正确决策框架｜INTERPRETATION**：完成有依据的比较和 gate 后交接动作；若要重开，应指出新观察、反馈或直接相关风险要求，而非换一种措辞。

**实际发生了什么｜FACT**：有界 top-two/stop 规则未可靠遵守，属于 RUNTIME_ADHERENCE_FAIL 的确认问题。

**事后能学到什么｜INTERPRETATION**：结束比较也是决策能力；规则可包含停止条件，不只是提醒多想风险。

**不能推出什么**：不能推所有长推理都无益，或仅靠缩短输出就会提高分数；报告没有测出此缺陷的独立成本和因果影响。

## C07｜重复汇报未增 Output：一次 no-gain 不是 STALLED

来源：[v6 运行验证](../../project/runs/v6-run1-validation.md)的重复准备汇报材料观察；不借用源图 E05 的 v7q 身份。

**事实背景｜FACT**：重复 `准备汇报材料` 未见 observed Output 增加，Agent 注意到这一点并选另一个 Energy 动作；该片段具体月份在报告中未列。

**Agent 当时能看到什么**：当前同局公开值与动作后新观察；不能用隐藏 cap 或内部资格解释未增长。

**相关规则**：observed effect 优先于 advertised effect；同动作、同 Gap、两个相邻可比 checkpoint 无目标进展才 STALLED，混杂／不可比 UNKNOWN。

**正确决策框架｜INTERPRETATION**：记录此次未见增长，比较当前路径价值；别把一次局部零响应升级为全局上限或严格停滞。

**实际发生了什么｜FACT**：选了另一项 Energy；报告明确 strict STALLED 未建立，P 是 NOT_TRIGGERED，不能写成遗漏。

**事后能学到什么｜INTERPRETATION**：合理的局部调整与一个正式诊断标签可以分开；没触发标签不等于模块没用。

**不能推出什么**：不能断言 Output 已封顶、同类动作永久无效或换路带来收益，也不能补写相邻两个复核点的目标值。

## C08｜418 个标记形状文本：可计数不等于可关联

来源：[v6 CTRL audit](../../project/runs/v6-run1-validation.md)。**FACT｜事实**：418 个 marker-shaped transcript occurrences 对应 203 次动作尝试；扁平 transcript 缺可靠 model-turn ID，不能认证逐动作配对、孤立/重复、覆盖率及同回合 X 门禁。

**INTERPRETATION｜反例判断**：文字计数不是决策计数。不能直接相除当遵循率，也不能因无法认证就认定所有 Risk 未执行。逐次关联与替代解释查[Forensics 的 CTRL/action 案例](../track-d-project-method/08-Forensics为什么成为项目的重要部分.md)，字段合同仍查[Instruction](02-exact-v6-Instruction逐句拆解.md)。

## C09｜v8a 两个 full-horizon 样本：同身份仍有不同轨迹

来源：源图 E07；[RUN07](../../project/runs/v8a-full-horizon-sample1.md)和[RUN08](../../project/runs/v8a-full-horizon-sample2.md)。**FACT｜事实**：同一冻结行为身份的两局均完成 48 月，量化分分别 72.65 与 59.00。两局都有隐藏数值引用的证据纪律限制；这些事后发现不能用于当时动作选择。

**INTERPRETATION｜反例判断**：当局仍只用本局公开状态、反馈和合法选项；事后保留两个结果，不挑高局代表稳定性能。两样本不能估计分布，不是 exact-v6 复验。样本单位及不确定性查[一次高分的限制](../track-d-project-method/07-为什么一次高分几乎什么都证明不了.md)；CTRL/DL 解析与语义边界查[Forensics](../track-d-project-method/08-Forensics为什么成为项目的重要部分.md)；完整候选比较查[最终交付报告](../../final-report/04-最终方案、候选选择与工程交付.md)。

## 失败分类：先分清问题落在哪一层

以下 taxonomy（分类框架）是 **INTERPRETATION｜工程诊断方法**，不是游戏隐藏机制，也不预设每个问题只有一个标签。

| 类型 | 要问的问题 | 本章可支持的定位 | 不能混淆成什么 |
|---|---|---|---|
| Policy design failure（政策设计失败） | 书面规则是否本身含糊、矛盾或缺必要边界？ | 本章多数问题有明确规则却执行未遵守；设计缺陷另需原文冲突证据 | 看到低分就认定设计错误 |
| Runtime adherence failure（运行遵循失败） | 实际行为是否满足已写合同？ | C05 重读遗漏、C06 无证据重开、C03 H 遗漏 | 文件不存在或单纯分数差 |
| Tool/schema failure（工具／格式失败） | 调用是否满足合法输入合同，环境是否实际改变？ | C04 明确执行前参数拒绝 | 任何失败都无副作用，或规划思想一定错误 |
| Evidence interpretation failure（证据解释失败） | 是否把未知、相关、宣传当确定事实？ | C07 的“零增长→隐藏 cap”会是错误推断；C09 信息违规是审计发现 | 用隐藏结果教当时选项 |
| Auditability failure（可审计性失败） | 能否把记录可靠绑定到动作与回合？ | C08 CTRL/action 配对不能认证，C02 标记重复 | 无法认证等于每次都错，或计数够就通过 |
| Statistical inference failure（统计推断失败） | 样本是否足以支持稳定性、分布或因果主张？ | C09 两个结果不够；v6 一个样本也不够 | 分数差就是 Skill 增益 |

**INTERPRETATION**：一件事可以有两个问题。例如 C04 的参数错误是已确认技术表达问题；若控制记录不能配到这次尝试，还另有审计缺口。C08 只能说门禁无法认证，不应扩大成“所有 Risk 都没有执行”。分类的意义是缩小结论与修复范围。

## 怎样写一段能被复核的案例结论

先写身份与观察，随后写对应规则及实际行为，最后保留未知。评价语要匹配证据：看到的是未触发，就写未触发；该做却没做且证据充分，写遗漏；存在文字但关联不全，写无法认证；没有干净比较，写 UNKNOWN。

**TEACHING EXAMPLE｜教学示例，不是历史 Run 原始记录。** 构造一段错误汇报：“选择恢复后晋升，所以恢复提高晋升率；CTRL 有两百多条，所以三 Skill 完全遵循。”请按本章方法改写。

参考改写：恢复与晋升是先后观察，不构成受控因果比较；CTRL 文本量不提供动作／回合关联，需要逐次合法对应与语义检查。若只有这些材料，收益、遵循率与稳定性均未证明。还应注明具体 Candidate 与 Run，不能把不同版本片段合成一个“理想成功局”。

**FACT｜最终证据边界**：[最终证据审阅](../../project/FINAL_EVIDENCE_REVIEW.md)仍将 exact-v6 记为一个完整样本与 RUNTIME_ADHERENCE_FAIL；v8a 双样本都有审计限制。官方上传与平台评测未执行。C01–C09 共九个可定位案例，但它们多数来自同一个 v6 Run，**不是九个独立实验样本**。
