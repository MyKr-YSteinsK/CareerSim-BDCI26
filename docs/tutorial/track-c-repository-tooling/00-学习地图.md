## 这条学习路线解决什么问题

打开 `D:\CS\CareerSim`，你会看到代码、Markdown、配置、实验结果和几个占用很大的点号目录。它们都在同一处，但使用者、产生时间和保留规则不同。Repository（代码仓库）首先是一组可以共同管理版本的文件；它也承载工程知识，并不意味着每个文件都会在一局游戏中被加载。

Track C 的目标是让你遇到陌生文件时，能依次问清六件事：**为什么存在、谁使用、什么时候产生、是否参与运行、它证明什么、退役条件是什么**。能回答这些问题，比记住某个目录共有多少文件更有用。

**FACT｜事实：**本教程基于 S11-29 的 `main@1c6231de36c98e4cdae38bba95c070d8750bcf65`，先读取 S11-28 的七份来源地图，再核对地图指定的代码与权威文档。当前比赛对局与 Candidate 搜索已关闭；S11 仍为 ACTIVE。本文是教学材料，不能授予对局、Provider（模型服务提供方）请求、安装、服务操作或清理权限。状态来源见[当前状态](../../project/CURRENT_STATE.md)与[运行合同](../../project/LIVE_RUN_WORKFLOW.md)。

## 阅读中的四种标记

- **FACT｜事实：**当前代码或注明身份的来源直接支持的内容。历史事实必须保留当时版本与验证范围。
- **INTERPRETATION｜解释：**将已知文件关系组织成便于理解的分类。这些分类不替代 Main 的正式决策。
- **TEACHING EXAMPLE｜教学示例：**人为构造的简化场景或演算。不能当成真实 Run、真实分数或测试执行记录。
- **UNKNOWN｜当前来源不足：**来源没有回答的问题。保留未知比补一个听起来合理的原因更准确。

例如，“某审计脚本输出 JSON”可以是事实；“它值得长期保留为复现工具”需要依赖与维护决策；“设想它收到两个不同 Session”是教学示例；“某个本机日志是否覆盖唯一失败窗口”在没有核对来源时就是未知。

本教程中的源码链接供定位，不要求你执行。所有可能改变文件、环境、服务或游戏的步骤均只是说明历史或教学关系；涉及操作时遵循：**教学示例；当前 S11-29 不授权执行。**

## 一个贯穿全书的判断题

**TEACHING EXAMPLE｜教学示例：**你看到 `s09_04_resource_trajectory_forensics.py`、某局的 `events.jsonl`、`post_run_summary.json` 和教程第 07 章。哪一份“最重要”？

答案取决于问题。重做资源轨迹提取需要脚本及准确输入；核对一次动作需要原始事件及 Session；快速审阅需要摘要；学习方法需要教程。它们属于不同依赖位置，不存在按扩展名就能排出的永久价值顺序。删除决策也因此不能只看 `.py`、`.json`、`.md` 或文件大小。
