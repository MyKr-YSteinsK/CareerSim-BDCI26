# 08｜答辩要点与常见问题

本文提供可直接练习的答辩结构。项目是 2026 CCF BDCI「华为 openJiuwen Agent 职场长程生存与晋升挑战」的公开 Dev 工程工作；所有本地运行分数都是项目运行记录，不是官方平台成绩。回答可以自信，但要把候选身份、样本数和验证边界同时说清楚。

术语首次出现时：Agent（智能体）负责作出决策；Skill（技能模块）提供有边界的职责规则；Planning（规划）是唯一策略规划职责；Risk Control（风险控制）只审查当前候选的直接重大后果；MCP（Model Context Protocol，模型上下文协议）承载工具请求与结果；Runner（运行器）组织本地运行和提交材料校验；Provenance（来源追踪）用于把结论对应到确切候选、运行、提交和记录。

## 1. 一句话项目介绍

### 15 秒版

我参与了一个长程职场模拟 Agent 工程项目，重点是把公开状态、规划、风险审核和可复核运行证据连成闭环。

### 30 秒版

项目面向 48 个月的职场生存与晋升模拟。最终冻结的是 Single Agent（单一智能体）加三个职责明确的 Skills，分别整理状态、滚动规划和审核候选风险。我们对单局成绩、运行遵循和交付身份分开审计；exact v6 有一条 75.29 的完整 Dev 样本，但运行遵循审计失败，不能说成稳定成绩或官方评测结果。

### 60 秒版

CareerSim 要求 Agent 在最长 48 个月的公开 Dev 模拟里不断观察状态、处理事件、分配资源并应对半年反馈。它的难点不仅是选一个看起来好的动作，还包括动作是否被工具接受、动作后有没有重新观察、上下文压缩后是否恢复了正确事实，以及不同轨迹之间能不能公平比较。最终冻结包采用 Single Agent + 3 Skills：`structured-state-board` 记录本局公开事实，`rolling-planning` 是唯一规划负责人，`risk-review` 只检查当前候选的直接重大风险。项目通过分层验证和负结果复盘避免把静态通过写成运行成功。exact v6 的一条完整样本得到 75.29 quantitative、52.70 competition partial、48 个月、A / L6，同时为 `RUNTIME_ADHERENCE_FAIL`。包身份可由 source、manifest 和 ZIP hash 核对，但官方上传和隐藏 Test 评测没有证据。

## 2. 3–5 分钟答辩主线

以下讲稿可以按约 5 分钟练习。括号中的资料用于准备，不必逐字念出来。

### 0:00–0:30｜问题是什么

我们的项目是 CareerSim BDCI26 的工程实践。Agent 需要在一个长程职场模拟里持续作决定，目标涉及生存、能力成长、交付、绩效反馈和晋升。它不是一次生成职业计划后就结束，而是每项行动都会改变之后的公开状态，Agent 必须继续观察、重新判断并作出下一项合法选择。

### 0:30–1:15｜为什么难

长时程带来三个互相影响的问题。第一，状态会变化，旧观察可能过期；第二，工具请求不等于模拟器已经接受动作；第三，完成一局不等于遵循了全部运行规则，更不等于策略具有因果收益。上下文压缩又会带来恢复问题：恢复后要确认还是同一局、重新观察并重新读入相关 Skill。项目因此把过程事实、运行遵循和最终分数分开记录。

### 1:15–2:15｜最终架构

最终冻结的是一个动作提交者和三个 Skills。状态板只回答“本局当前公开可确认什么”；规划模块是唯一策略负责人，维护一个有公开依据的主要缺口和剩余机会窗口；Risk 只审核已经形成的当前候选是否有直接相关的重大公开后果。最终动作仍由单一 Agent 提交。动作改变状态以后必须 fresh observe，再规划下一项行动。这样拆分是为了让职责、输入和权限便于审计；它不是多 Agent 对照实验，也不证明三个 Skill 数量是普遍最优。

### 2:15–3:15｜研发与实验方法

项目先从可观察的公开轨迹提出问题，再按包格式、安装、发现、加载、真实情境调用、动作回执和运行效果逐层验证。S03 的早期 Risk smoke 通过了若干静态和加载门，但工具路径与 CareerSim 不匹配，没有进入真实游戏行为验证，所以策略收益仍未证明。之后的实验也分别在部署、信号或可行性门停下。我们不把“没有运行”误写为“运行后无效”，也不把时间上的先后关系写成动作因果。

### 3:15–4:15｜最终结果

被接受的 exact v6 完整样本为 75.29 / 52.70 / 48 个月 / A / L6。审计同时发现 203 次动作尝试中有一次 Energy 多选请求被拒绝；202 次成功状态改变动作都在之后重新观察，但还有半年标记遗漏、无新证据时反复重开普通 Story 讨论、动作标记配对不可认证，以及压缩后未重读三个 Skills。因此这条轨迹是一次有效完整终局，也是一条运行遵循失败的样本。Candidate v1 曾有 76.04 单次结果，v8a 也有两条不同完整轨迹；我们保留这些反例，没有把 v6 称为所有历史分数第一。

### 4:15–5:00｜工程价值与限制

工程交付方面，最终包绑定 exact source、三份 Skill 身份、manifest 和七文件 ZIP hash；当前 main checkout 的历史 v8a 状态与冻结包分开说明。项目展示的是长程 Agent 职责设计、工具链审计、实验边界和来源追踪的实际工作。它不能证明稳定成绩、策略因果提升、隐藏集迁移、官方上传成功、奖项或名次。下一步的讨论应建立在新的授权和可比较证据上，而不是从这一个分数外推。

可核验入口：[架构复盘](../project/ARCHITECTURE_RETROSPECTIVE.md)、[实验复盘](../project/EXPERIMENT_RETROSPECTIVE.md)、[最终方案审阅](../project/FINAL_SOLUTION_REVIEW.md)、[S06 closeout](../project/S06_CLOSEOUT.md)。

## 3. 10–15 分钟技术答辩结构

| 时间 | 内容 | 核心图/表 | 一定要说 | 不要说 |
|---|---|---|---|---|
| 0:00–1:00 | 赛题与运行对象 | 48 个月的状态—行动闭环图 | 本地公开 Dev 与隐藏 Test 是不同证据 | 本地分数就是官方成绩 |
| 1:00–2:15 | 长程问题 | 状态变化、反馈重置、压缩恢复示意 | 状态过期、动作回执和规划周期同时重要 | 每月都有固定相同菜单 |
| 2:15–3:30 | 最终架构 | Single Agent + 3 Skills 职责图 | 一个动作提交者；一个 Planning owner；Risk 是候选门 | 三个 Skill 是三个投票 Agent |
| 3:30–4:45 | Action loop | observe→Board→Planning→Risk→action→observe | 意图、请求、回执和新状态是不同层 | 模型说“选 B”就证明环境执行 B |
| 4:45–6:00 | 状态、规划、风险 | 三职责输入/输出/禁止权限表 | 新鲜公开事实优先；未知保留未知 | 固定阈值或故事编号规则 |
| 6:00–7:15 | 实验方法 | 验证层级阶梯 | 静态、加载、真实情境、遵循和收益逐层区分 | 一个 PASS 代表端到端有效 |
| 7:15–8:30 | Candidate 演进 | v1、v6、v8a 结果与边界表 | 同身份也有轨迹差异；版本不可直接归因 | 只展示最高分样本 |
| 8:30–9:45 | 失败与负结果 | 技术失败/自然终局/部署失败分类表 | v7m 没有终局分数；S03 smoke 未进真实游戏链 | 把所有未完成路线叫策略失败 |
| 9:45–11:00 | 最终选择 | source→manifest→ZIP provenance 图 | exact v6 是范围受限的工程冻结选择 | v6 是历史最高或统计最优 |
| 11:00–12:15 | 工程交付 | 七文件包、hash 与本地校验边界 | 离线材料校验不等于云端/官方评测 | 平台已接收或验证 |
| 12:15–13:30 | 限制与问答 | 已知/未知/未测试表 | adherence fail、隐藏集未知、Team/Swarm 未测 | 稳定 75+、TOP5 或获奖 |

可把这 12 分钟结构压到 10 分钟，方法是减少版本背景和实验细节，不删掉结果的证据边界。若时间扩展到 15 分钟，可在第 6 分钟多讲一个单机制实验范例，在第 8 分钟解释一个技术中断与自然终局的差异。不要用超时堆更多分数；让每一页都回答一个问题。

## 4. 高频答辩问题

每题都同时准备“推荐回答”和“停止线”。证据链接指向工程记录；如果追问超出来源范围，承认未知比现场猜答案更可靠。

### 1. 为什么选 Single Agent，不用 Multi-Agent？

- **推荐回答：**当时没有证据表明必须由多个独立 Agent 才能解决瓶颈。职责拆分保留在同一 Agent 的三个 Skills 中，所有动作只有一个提交者，便于确认状态与最终动作的归属。
- **证据依据：**[S06 closeout](../project/S06_CLOSEOUT.md)、[架构复盘](../project/ARCHITECTURE_RETROSPECTIVE.md)。
- **不应扩展成：**多 Agent 不适合这道题或已被实验否定；Team/Swarm 是 `DEFERRED / NOT_TESTED`。

### 2. 为什么是三个 Skills？

- **推荐回答：**三个模块分别承担事实整理、唯一策略规划和候选风险审核，责任边界不同。这个数量是冻结方案的身份，不是通过比较证明的理论最优拆分。
- **证据依据：**[最终身份](../project/FINAL_SUBMISSION_IDENTITY.json)、[架构复盘](../project/ARCHITECTURE_RETROSPECTIVE.md)。
- **不应扩展成：**三 Skill 已被证明胜过四 Skill 或其他架构。

### 3. `structured-state-board` 到底解决什么？

- **推荐回答：**它整理同一局最新公开状态、数据来源和新鲜度，减少把长对话或旧快照误作当前事实；证据不清时保留 UNKNOWN。
- **证据依据：**exact-v6 Skill 身份和[架构复盘](../project/ARCHITECTURE_RETROSPECTIVE.md)。
- **不应扩展成：**它读取隐藏状态、提供因果归因或自动决定策略目标。

### 4. Planning 怎么体现 long-horizon？

- **推荐回答：**它滚动维护一个公开目标缺口、可比较进展、公开生存趋势和剩余可兑现窗口，并在正式反馈后重置比较基线；不是固定每月动作表。
- **证据依据：**[S06 closeout](../project/S06_CLOSEOUT.md)、[最终方案审阅](../project/FINAL_SOLUTION_REVIEW.md)。
- **不应扩展成：**使用未公开晋升阈值或精确的隐藏时间切换公式。

### 5. Risk 为什么不是第二个 planner？

- **推荐回答：**Risk 只检查当前合法候选的直接相关重大公开后果；它能要求一次有界替代比较，但不拥有 Primary Gap、一般行动排序或最终动作权。
- **证据依据：**[架构复盘](../project/ARCHITECTURE_RETROSPECTIVE.md)、[最终 Skill 身份](../project/FINAL_SUBMISSION_IDENTITY.json)。
- **不应扩展成：**Risk 会接管全局策略，或关键词命中自动否决所有候选。

### 6. MCP 在系统中是什么角色？

- **推荐回答：**MCP 是 Agent 与 career-emulator 工具交换 observe、动作请求和结果的接口。它是工具通信层，不是另一个规划模型。
- **证据依据：**[官方来源锁](../project/OFFICIAL_SOURCE_LOCK.md)、[赛题与项目总览](01-赛题与项目总览.md)。
- **不应扩展成：**MCP 请求发出就代表环境已执行。

### 7. 如何保证模型“说选 B”真的变成环境执行 B？

- **推荐回答：**不能只靠自然语言保证。审计要核对实际 MCP 请求参数、模拟器回执，以及动作后的新观察；拒绝、超时和状态改变分别记录。
- **证据依据：**[v6 运行记录](../project/runs/v6-run1-validation.md)、[S06 closeout](../project/S06_CLOSEOUT.md)。
- **不应扩展成：**202 个正确 observe 配对就证明全局运行完全正确；该局还有其他 adherence 缺陷。

### 8. context compression 怎么处理？

- **推荐回答：**恢复时确认仍是同一 session，先取得 fresh observe，再重建状态板和规划状态并重读相关 Skills。v6 的两次压缩后均没有重读三份 Skills，所以实际遵循没有通过。
- **证据依据：**[v6 运行记录](../project/runs/v6-run1-validation.md)、[架构复盘](../project/ARCHITECTURE_RETROSPECTIVE.md)。
- **不应扩展成：**写了恢复规则就代表运行已执行恢复。

### 9. 为什么最终 v6 有 75.29，却还叫 adherence fail？

- **推荐回答：**成绩和运行合同是两条不同轴。它走满 48 个月并得到终局值；审计同时发现被拒绝的 Energy 请求、半年标记遗漏、重复讨论、动作标记配对问题和压缩后未重读 Skills。
- **证据依据：**[v6 run record](../project/runs/v6-run1-validation.md)、[S10-23R audit](../project/reviews/S10-23R_FINAL_SINGLE_SHOT_FREEZE.md)。
- **不应扩展成：**只要分数高就可以忽略执行缺陷，或缺陷使分数不是真实观测。

### 10. 为什么不选 Candidate v1 的 76.04？

- **推荐回答：**76.04 高于 v6，所以 v6 不是全历史最高。v1 另一局是 35.31 / 25m / D / L4，原始轨迹不可用；Main 选择的是有完整来源身份和可审计轨迹的成熟三 Skill 候选，不是单纯按峰值排序。
- **证据依据：**[最终证据审阅](../project/FINAL_EVIDENCE_REVIEW.md)、[S06 closeout](../project/S06_CLOSEOUT.md)。
- **不应扩展成：**v6 的策略效果被证明优于 v1。

### 11. 为什么不选 v8a？

- **推荐回答：**v8a 是不同的四 Skill Candidate，两个完整样本是 72.65 和 59.00；它不是 exact-v6 复验，也没有与 v6 形成同条件架构比较。最终 ZIP 的冻结身份仍是 exact v6。
- **证据依据：**[v8a 两样本审阅](../project/FINAL_EVIDENCE_REVIEW.md)、[最终 manifest](../project/FINAL_SUBMISSION_MANIFEST.md)。
- **不应扩展成：**三 Skill 已经被证明比四 Skill 更好。

### 12. v8a 的 72.65 / 59.00 说明什么？

- **推荐回答：**同一 Candidate 有两条不同的 48 个月轨迹，说明单个运行不能代替分布；这两个点仅支持描述样本差异，不足以估计稳定性或和 v6 作因果比较。
- **证据依据：**[样本一](../project/runs/v8a-full-horizon-sample1.md)、[样本二](../project/runs/v8a-full-horizon-sample2.md)。
- **不应扩展成：**四 Skill 导致分数下降，或 v8a 的期望成绩就是两点均值。

### 13. 单局高分能证明什么？

- **推荐回答：**它证明这条特定身份与运行轨迹确实得到记录的结果，并可用于逐局行为复盘。没有重复样本和可比对照，它不能证明稳定分布、因果收益或隐藏集迁移。
- **证据依据：**[实验复盘](../project/EXPERIMENT_RETROSPECTIVE.md)、[最终证据审阅](../project/FINAL_EVIDENCE_REVIEW.md)。
- **不应扩展成：**“项目稳定拿到这个分数”。

### 14. 为什么没做更多重复实验？

- **推荐回答：**最终冻结是一次提交材料的工程决策，不是分布估计研究。v6 replication 被记录为不需要用于最终构建，S06 也没有授权额外对局；因此分布仍未知，不能把样本限制包装成优势。
- **证据依据：**[最终身份](../project/FINAL_SUBMISSION_IDENTITY.json)、[S06 closeout](../project/S06_CLOSEOUT.md)。
- **不应扩展成：**“一个样本足以证明候选表现”，或擅自推断没做实验的全部原因。

### 15. 如何避免对 Dev 过拟合？

- **推荐回答：**运行时设计依赖当前 session 的公开状态、合法选项和正式反馈，不把局后分析转成故事编号答案、隐藏阈值或固定配方。Dev 轨迹用于提出和检查假设，不等于隐藏 Test 验证。
- **证据依据：**[官方来源锁](../project/OFFICIAL_SOURCE_LOCK.md)、[实验复盘](../project/EXPERIMENT_RETROSPECTIVE.md)。
- **不应扩展成：**已经证明对隐藏分布完全没有过拟合。

### 16. hidden rules 有没有用？

- **推荐回答：**没有把隐藏计数、阈值或评分权重写进最终 runtime lookup。历史取证用于识别研究问题；参赛 Agent 的依据仍限于参与者可见信息。
- **证据依据：**[官方来源锁](../project/OFFICIAL_SOURCE_LOCK.md)、[S06-16 架构审查](../project/reviews/S06-16_FINAL_CONTROL_ARCHITECTURE_REVIEW.md)。
- **不应扩展成：**我们知道完整隐藏规则，或已经验证这些规则在隐藏 Test 的效果。

### 17. Memory 为什么没进最终方案？

- **推荐回答：**被测的是冻结路径的自动 `MEMORY.md` anchor，它在捕获中没有带出正文；显式读取可用。这个自动持久化部署门未过，因此没有进入包，但不代表所有记忆设计都无效。
- **证据依据：**[Memory feasibility](../project/research/S10-19R2_MEMORY_FEASIBILITY.md)、[最终证据审阅](../project/FINAL_EVIDENCE_REVIEW.md)。
- **不应扩展成：**Memory 普遍不可行或会降低成绩。

### 18. Reviewer 为什么没进？

- **推荐回答：**在冻结提交路径中没找到已注册且机械只读的安全 Reviewer 部署入口；安全门未过，所以后续质量评测没有运行。这是部署结论，不是审查价值结论。
- **证据依据：**[Reviewer feasibility](../project/research/S10-19R1_SUBAGENT_FEASIBILITY.md)。
- **不应扩展成：**已做过独立盲审并发现它无效。

### 19. Team/Swarm 为什么没做？

- **推荐回答：**项目没有完成其部署或对照实验，状态应写 `DEFERRED / NOT_TESTED`。当前架构优先让动作权只有一个 owner，减少本项目已有证据范围内的状态归属歧义。
- **证据依据：**[S06 closeout](../project/S06_CLOSEOUT.md)、[架构决策](../project/ARCHITECTURE_DECISIONS.md)。
- **不应扩展成：**多 Agent 一定不适合或一定更差。

### 20. 项目最大失败是什么？

- **推荐回答：**最明确的重大限制之一是唯一完整 exact-v6 样本仍为 `RUNTIME_ADHERENCE_FAIL`，说明交付前设计合同与长程运行中的实际遵循没有完全闭环。另一类流程教训是早期 smoke 没接入正确的游戏工具链。
- **证据依据：**[v6 run record](../project/runs/v6-run1-validation.md)、[研发演进报告](03-完整研发流程与方案演进.md) 中的 S03-02 历史复盘。
- **不应扩展成：**每一个策略选择都失败，或所有问题已有修复验证。

### 21. 最大工程挑战是什么？

- **推荐回答：**把设计文本、框架装载、模型调用、工具回执、新鲜状态、最终成绩和打包身份分层。只要将其中两层混为一谈，就可能把文件存在写成运行有效，或把本地包冻结写成平台受理。
- **证据依据：**[实验复盘](../project/EXPERIMENT_RETROSPECTIVE.md)、[最终 manifest](../project/FINAL_SUBMISSION_MANIFEST.md)。
- **不应扩展成：**已经解决了所有模型运行时可观测性问题。

### 22. 最终包如何保证身份一致？

- **推荐回答：**记录 source commit、runtime manifest、三份 Skill blob、构建 commit、七个 ZIP 成员与逐文件/整体 SHA-256，再按冻结流程做本地离线校验。它能确认被冻结的本地工件，不会证明平台收到该包。
- **证据依据：**[最终身份 JSON](../project/FINAL_SUBMISSION_IDENTITY.json)、[manifest](../project/FINAL_SUBMISSION_MANIFEST.md)、[冻结审计](../project/reviews/S10-23R_FINAL_SINGLE_SHOT_FREEZE.md)。

### 23. 当前 main 为什么不是 final v6？

- **推荐回答：**冻结 ZIP 来源是历史 exact v6；后续主仓库保留了 v8a 四 Skill 工程状态。当前 checkout 的时间更晚，但不自动变成旧包的来源。

## 5. 高风险问题回答

### “你们是不是挑最好一局？”

承认项目按成熟三 Skill 路线和可核对身份冻结 exact v6，但同时保留 Candidate v1 的 76.04 反例、v1 的另一条低分轨迹、v8a 的两条差异轨迹和 v6 的 adherence fail。最终选择不是全历史数字取最大；它是在当时证据质量和提交身份约束下作出的工程决定。样本数量仍不足以估计分布。

### “75.29 不是最高为什么还选？”

因为 75.29 不是选择理由的全部。v1 的单次 76.04 更高，但 raw 轨迹不可用，另一局为 35.31；v6 有清楚的 source、Skill blob、运行记录、manifest 和 ZIP hash。选择说明可审计身份优先，不说明 v6 的策略因果上胜过 v1。

### “这个架构真的有效吗？”

回答“有效”前先限定指标。v6 的一次运行里观察到过若干预期机制，但唯一完整样本运行遵循失败；项目没有用受控消融将最终成绩归因给 Board、Planning 或 Risk。能确认的是架构职责被定义并冻结，不能确认各 Skill 的分数贡献。

### “没有 hidden test 结果，这个项目有什么意义？”

它提供的是公开 Dev 工程流程、工具正确性审计、候选身份治理和实验结论边界的实例，不能代替官方性能结论。若岗位评估只看隐藏测试成绩，这项工程材料的限制应直接承认。

### “为什么不 Multi-Agent？”

因为没有完成对照，不应说“它更差”。当前选 Single Agent 是当时让动作 authority 清楚的实现选择；多 Agent 的协调成本和潜在收益都没有通过本项目实验测量。

### “这么多规则是不是过拟合？”

规则的依据限定为当前局公开状态、合法选项和确认回执，故意没有故事标题答案表或隐藏阈值；但这只能说明设计采用可见信息边界，不能证明绝对不存在对 Dev 的过拟合。最终 v6 单样本与 adherence 缺陷仍限制结论。
