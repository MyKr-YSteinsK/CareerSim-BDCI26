# 05｜失败路线与负结果复盘

## 1. 先把“失败”分成不同类型

一个 Agent 项目里，调用接口错误、自然提前终局、运行契约漏项、策略信号不足和部署路径不可用，都可能被口语称为“失败”。但它们回答的问题不同：

| 类型 | 例子 | 正确解释 |
|---|---|---|
| 技术中断 | v7m 在 M20 Runner 技术失败 | 没有终局成绩；作为技术证据留存。 |
| 自然终局 | v7q 在 M24 以 E / L1 结束 | 一条低分自然终局轨迹；不证明某个动作必能避免它。 |
| 执行契约失败 | exact v6 走满 48 个月但为 RUNTIME_ADHERENCE_FAIL | 完整终局事实与运行遵循缺陷同时成立。 |
| 策略信号弱 | Replay controller 24 案例只见 1 次状态级修正，8 个 UNKNOWN | 当前控制器逻辑不足以支撑部署，不等于所有控制器无效。 |
| 部署门未过 | 冻结 rail 没有已注册的只读 Reviewer 路径 | 后续质量评测未运行；不是独立审查无价值的结论。 |
| 可行性不足 | Simulator search 基线仅 2/16 完成 | 宏策略比较没有开展，无法判策略好坏。 |

把边界写清楚能够保留失败的工程价值：它让后续负责人知道是修 Runner 路由、改审计合同、补实验还是等待新的部署条件，而不是继续重复一个没有回答原问题的运行。

## 2. 早期 Risk smoke 没有进入游戏链

S03-01 用 S01 公开时间线提出风险复核假设：M2 出现公开警告，M10、M12、M18 有相关风险反馈，M19 出现 trust-crisis 自然终止。它是同局时间关系，不提供动作级因果证据。

S03-02 的 risk-review Skill 通过 frontmatter、安装、Runner 验证、运行时发现和内容加载；唯一有界 smoke 却使用了不匹配 CareerSim 的通用工具路径。它没有创建 CareerSim session，也没有 observe、候选或 take_action 链。因此没有 Risk 触发窗口、候选替换记录或策略收益样本，结论为 `RISK_BENEFIT=NOT_PROVEN`。正确复盘不是把 Skill 判为有效或无效，而是指出验证链停在了哪一层。[S03-01 取证记录](https://github.com/MyKr-YSteinsK/CareerSim-BDCI26/blob/488017113fe3ab491dada55be478870f1447c0cf/experiments/S03-01-risk-forensics/RESULT.md) · [S03-02 运行结果](https://github.com/MyKr-YSteinsK/CareerSim-BDCI26/blob/488017113fe3ab491dada55be478870f1447c0cf/experiments/S03-02-risk-review/RESULT.md)

## 3. 轨迹差异和运行缺陷

### S01 与 v4：发现问题，不等于证明解决方案

S01 no-op 基线在第 19 个月自然终止，结果为 26.95 / 18.86 / E / L3。早期 v4 一局在 M6 因 Health 归零结束。两次轨迹帮助团队关注生存资源、公开风险和长期规划，但不能证明加入 Risk 或 Planning 后一定能延长时程。后续架构变化和运行环境变化也使两端分数不是一项单变量比较。

### Candidate v1：单次峰值与另一条轨迹并存

Candidate v1 留有一局 76.04 / 48m / A / L6，另一局为 35.31 / 25m / D / L4。两者是显著不同的历史结果；现存材料属于 Tier-B 摘要，原始 raw 轨迹不可用，不能事后建立逐动作因果或稳定分布。76.04 高于 exact v6 的 75.29，因此不能声称 v6 是全历史最高分；最终选择是身份和审计质量约束下的工程决定。

### v7g、v7q、v7m：完成、自然终局与技术失败分开看

v7g 的一局完成 48 个月，得到 54.52、C / L5，同时有策略与运行遵循缺陷。v7q 在 M24 自然结束，量化值 26.80、competition partial 18.76、E / L1。v7m 在 M20 技术中断，没有最终分数或 grade。三者分别展示低表现完整运行、自然提前终局和技术中断的证据形态；技术停止不能记成低策略分，完成时程也不等于运行审计通过。

### exact v6：好结果与运行契约缺陷同时存在

exact v6 的一条完整局得到 75.29 / 52.70 / 48m / A / L6，但最终审计仍为 `RUNTIME_ADHERENCE_FAIL`。记录包含 203 次 take_action 尝试：202 次成功状态改变且随后有 fresh observe；一次 `choice=6,7,3` 的 Energy 请求被参数解析拒绝，未改变状态。此外还漏掉半年 H 标记、无新证据却重开普通 Story 讨论、自由文本 CTRL 与动作不能可靠配对，以及两次压缩后未重新读取三个 Skills。

这些发现不应被轻描淡写成“少量小问题”，因为它们分别影响请求正确性、事件流程、决策有界性、动作可审计性和压缩恢复。它们也不抹除本局确实完成 48 个月的事实。后续 v6b 静态补充了动作标记、Energy 单项提交和压缩恢复合同，但这些文案没有进入最终 v6 ZIP，也没有 v6b 运行验证，不能反向修复 v6 的审计状态。[v6 运行记录](../project/runs/v6-run1-validation.md) · [S06 closeout](../project/S06_CLOSEOUT.md)

### v8a：同一身份不保证同一分数

同一冻结四 Skill Candidate 的两个完整样本为 72.65 / 48m / A / L5 和 59.00 / 48m / C / L4。这个差异说明两条轨迹不同，不是精确的策略因果实验，不构成稳定分布，也不是 exact v6 的复验。v8a 和 v6 还具有不同的 Skill 集合及 Candidate 身份，不能把这两组数字拼成一个架构对照。[v8a 样本一](../project/runs/v8a-full-horizon-sample1.md) · [v8a 样本二](../project/runs/v8a-full-horizon-sample2.md)

## 4. 高级路线停在哪道门

| 路线 | 实际负结果或边界 | 可作出的结论 | 不能推出的结论 |
|---|---|---|---|
| Reviewer / subagent | 冻结提交轨道未找到已注册且机械只读的审核路径；后续质量阶段未运行。 | 该 rail 不满足当前安全部署条件。 | 独立审核没有价值或盲审无效。 |
| 自动 Memory anchor | 指定冻结路径捕获中自动 MEMORY.md 正文缺失，显式读取可用。 | 这条自动注入路径未达到部署门。 | Memory 普遍无效，或记忆不会带来收益。 |
| Deterministic helper | 隔离 tool rail 中固定公开状态读写成功，但没有成为 Candidate。 | 工具层 challenger 获支持。 | 云端权限可用、模型会调用、遵循稳定或游戏收益成立。 |
| Replay controller | 24 个案例只有一次状态级修正，8 个 UNKNOWN，重要决策错误未证明被修复。 | 当前逻辑信号弱，不足以支持部署。 | 所有 controller 都无法修复决策。 |
| 策略挖掘 | 13 个运行的 82 个已完成窗口与 28 对匹配记录仍有选择、状态和延迟后果混杂。 | 可描述样本中的共同变化，形成后续问题。 | 匹配结果是受控因果效应或安全规则。 |
| Simulator policy search | 12 个宏配置已定义，冻结故事基线仅 2/16 完成；只运行基线，没有 search / holdout。 | 可行性门未过，策略比较没有开展。 | 搜索空间已经证明无效或某宏策略输给 baseline。 |
| Team / Swarm | 没有完成部署或对照运行。 | `DEFERRED / NOT_TESTED`。 | 多 Agent 不可行或会降低成绩。 |

跨路线最稳妥的结论是：这些探索没有产生一个证据充分且可提交的 Candidate 增量。每条路线失败在不同层，不能合并为“复杂方法都失败”。具体记录见[实验复盘](../project/EXPERIMENT_RETROSPECTIVE.md)、[架构复盘](../project/ARCHITECTURE_RETROSPECTIVE.md)与各路线 gate。

## 5. 负结果为什么有用

负结果能减少重复成本，前提是记录足够具体：当时身份是什么、哪个测试运行了、通过或失败的最后一层是什么、原始材料是否仍可恢复、未执行的后续阶段有哪些。S03 smoke 的接口错配提示更早校验真实工具路由；Reviewer 的部署门未通过就应停止质量评测；Simulator search 基线完成率不足时，不应继续讨论宏策略得分。

项目用 `NOT_PROVEN`、`NOT_TESTED`、`TECHNICAL_FAILURE`、`STRATEGY_SIGNAL_WEAK` 和 feasibility gate 区分不同情况。这些不是措辞细节，而是防止未来报告把“没有测”误读成“测了但没用”，或者把工具中断写成策略负效果。记录原始身份和 hold 也很重要：当结论仍依赖 raw 时，摘要和哈希都不能代替唯一来源。

## 6. 面试或复盘时的准确表达

推荐用一句话包含结论与边界：

- “S03-02 验证了 Skill 的若干静态和加载门，但 smoke 工具链不匹配，没有进入 CareerSim 行为验证，所以风险收益仍未证。”
- “exact v6 有一条 48 个月 A / L6 样本，同时运行契约审计失败；它是强完整样本，不是稳定策略证明。”
- “Replay controller 和 Simulator search 分别停在信号门与可行性门，不能把未完成比较概括成策略失败。”

主要事实与结论边界见[最终证据审阅](../project/FINAL_EVIDENCE_REVIEW.md)、[项目复盘](../project/PROJECT_RETROSPECTIVE.md)和[最终方案审阅](../project/FINAL_SOLUTION_REVIEW.md)。
