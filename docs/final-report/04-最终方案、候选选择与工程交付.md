# CareerSim｜最终方案、候选选择与工程交付

## 最终决定

项目冻结 **historical exact-v6** 作为最终比赛方案。所选身份是一个成熟的三 Skill 方案，有一条有效完整运行记录，也有明确的运行遵循缺陷。选择它不意味着它是全部历史最高分、统计赢家或全局最优。

本篇集中维护最终 Candidate、候选对比、adherence 限制与 ZIP 身份。其它报告引用摘要，不另建详细交付表。正式工件依据权威身份与 manifest；报告完成没有重建包、修补运行内容或执行官方上传。

### v1：反例必须与峰值一起保留

两条 v1 记录绑定到同一来源，属于 same-source pair（同源样本对）。第一局高于 v6 的量化分，第二局却提前终止。这组记录直接反驳“v6 是全部历史最高单局”及“看到最高分即可选定方案”的说法。

但它不构成受控分布：当前比较依据 Tier-B 历史摘要，原始 raw 不可用，完整 Instruction 身份也存在缺口。不能从两点计算可靠稳定性，也不能把低局结果因果归给某个 Skill。[S06 收口](../project/S06_CLOSEOUT.md)

### exact-v6：完整样本与遵循失败同时有效

RUN-0001 记录为 VALID_48M_COMPLETION，晋升点为 **M6 / M12 / M18 / M36 / M48**，最终 L6。记录末尾的 fresh observe 显示行政性的 M49 状态，计分结果仍是 48 个月，不应把它改为 49 个月成绩。[v6 运行原件](../project/runs/v6-run1-validation.md)

这条轨迹提供完整运行和局部机制观察，只有一个样本。其 Adherence（运行遵循）结论是失败；后续修复文本没有经过这一次运行，也不属于最终原始身份。包冻结没有把缺陷“变成通过”。

### v8a：两个轨迹，不能转移到 v6

两个 v8a 样本具有 same frozen behavior identity（同一冻结行为身份），结果不同。两个样本足以展示观测差异，不足以估计稳定分布或识别某个机制的因果效果。

它们不是 exact-v6 的 replication（复验），也不是保持其他条件可比较的三 Skill 与四 Skill 对照。不能把 v8a 的样本数或较低结果转移到 v6，作为其稳定性或优越性的证据。[v8a 样本 1](../project/runs/v8a-full-horizon-sample1.md) · [样本 2](../project/runs/v8a-full-horizon-sample2.md)

## 3. 为什么最终选择 exact-v6

### 已接受的事实

权威记录采用 HIGHEST_OBSERVED_MATURE_THREE_SKILL_CEILING，表示 Main 在现有记录的成熟三 Skill 路线中选择观察到的高位方案，并冻结其 exact source identity。该选择保留 v1 的历史更高单局反例，未将后续 v8a 或 fallback 成绩并入 v6。

最终冻结还落实用户明确选择：不产生新 Candidate，不改变行为，不改投另一 fallback，也没有为了打包增加一次复验。策略搜索关闭与最终身份固定属于治理决定，不是追加实验结果。[最终方案审阅](../project/FINAL_SOLUTION_REVIEW.md) · [最终冻结审计](../project/reviews/S10-23R_FINAL_SINGLE_SHOT_FREEZE.md)

### 对选择的工程解释

这一决定可以理解为在有限证据下同时考虑架构成熟度、已观察完整轨迹、来源可审计性、复杂度与冻结边界。三 Skill 的责任已经明确，运行与工件能够绑定到具体来源；后续研究没有形成足以替换它的安全部署与收益证据。

这里的“可以理解”是 **INTERPRETATION（解释）**，不是额外比较实验。它不证明三个 Skill 胜过四个，也不证明更低复杂度一定更高分。审计价值是可以准确说明发生什么及缺什么，不是把有缺陷的运行认证为正确。

### 三个直接问题

**为什么不是 v1？**单局峰值不能单独决定最终方案。v1 的同源低局和较弱原始来源同时保留；accepted selection 选的是成熟三 Skill 身份，而非只按全部历史单局最大值排序。

**为什么不是 v8a？**它属于不同架构与行为身份，两局有明显轨迹差异和运行、证据限制。它不是 v6 复验，也没有形成证明其更优的受控比较。

**v6 是否已经被证明最好？**没有。一个完整样本不提供稳定分布、因果提升或隐藏集表现；75.29 不能当成期望分数。冻结完成的是一项有边界的工程决策。

## 4. exact-v6 的遵循缺陷

### 必须保留的发现

| 发现 | 实际证据 | 影响与非结论 |
|---|---|---|
| Energy 多选 schema rejection | 一次提交 choice=6,7,3 被工具参数解析拒绝，动作未执行、状态未改变 | 是接口使用缺陷；不能算成成功行动，也不是自然游戏惩罚 |
| 压缩后未按要求重读 Skills | 两次 CurrentRoundCompressor epoch 后均没有三 Skill reread | 没完成恢复 rebuild；不能因最终通关忽略 |
| ordinary Story 无新证据重开讨论 | 普通事件多次重新 deliberation，有界比较规则未可靠遵守 | 说明执行效率与决策关闭存在问题；收益损失大小没有估计 |
| CTRL/action auditability ambiguity | 自由文本标记缺可靠 model-turn ID，不能认证完整配对、缺失或重复 | 出现标记不能当成逐动作遵循证书 |
| 半年度必需 H marker 遗漏 | review / promotion 点发生，但没有要求的 H 标记 | 违反控制合同；不是没有发生晋升 |

来源：[v6 runtime adherence audit](../project/runs/v6-run1-validation.md) 与 [最终方案审阅](../project/FINAL_SOLUTION_REVIEW.md)。这些发现不能概括成“minor”后略过。

### 哪些局部要求有支持

该局去重后的 take_action 尝试为 203 次，其中 202 次成功改变状态，一次参数拒绝。202 次成功状态改变后，都在下一次成功状态改变前取得了 fresh observe；这一范围内没有观测到 fresh-state 违规。

这是一项明确的局部遵循事实。它不覆盖标记、压缩恢复与普通事件推理，也不覆盖其它样本。不能用“202 次刷新通过”抵消整局 RUNTIME_ADHERENCE_FAIL，更不能把 action 成功数当作完成了全部执行协议。

### 为什么仍可作为有效 gameplay 证据

VALID_48M_COMPLETION 判断这条游戏轨迹是否有效完成；RUNTIME_ADHERENCE_FAIL 判断运行是否遵守所设合同。两者独立，因此可以同时成立。

冻结选择接受了该完整样本作为有边界参考，并保留已知缺陷。它没有宣称模型行为全部正确，也没有把 v6b 等后续静态修复移植到原始提交身份。否则，成绩将属于旧行为、报告却描述新行为，来源链会失去一致性。

## 8. 交付的可复核性与限制

项目能够指明行为来源、构建来源、工件字节身份和代表运行原件，避免混交当前 checkout 或其它候选。复核者可以沿这些入口检查材料；必要 raw 仍按来源约束留存。

但可复核并不意味着所有问题已经闭合。最终样本的 score report 本地副本曾出现 session 字段变化，原因未知；运行来源通过其它记录独立识别。v6 raw 正式 hold 状态也保留 UNKNOWN，不能写成“无保留约束”。细节由 [运行原件](../project/runs/v6-run1-validation.md) 与 [最终证据审阅](../project/FINAL_EVIDENCE_REVIEW.md) 管理。

这份交付的可信度来自明确身份及不隐瞒限制。它不是一份稳定性能保证，也没有比赛获奖、排名、独立核验的平台评分或 hidden-transfer 证明；用户报告的官网综合评分见下节。
