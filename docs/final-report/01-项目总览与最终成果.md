# CareerSim｜项目总览与最终成果

## 项目摘要

CareerSim 是一个长程 Agent 决策项目：在最长 48 个月的职业模拟中，Agent 持续读取公开状态、选择合法行动，并在成长机会、资源约束与生存风险之间调整计划。项目最终冻结的是 **Single Agent（单智能体）+ 三个 Skill（技能模块）** 的 exact-v6 方案，同时建立了运行身份记录、遵循审计和可追溯打包流程。

代表性本地结果来自一个完整运行样本：量化分 **75.29**，比赛局部得分 **52.70**，存活 **48 个月**，评级 **A**，职级 **L6**。该样本同时被判定为 **RUNTIME_ADHERENCE_FAIL（运行契约遵循失败）**。赛后另有三份官网综合评分为用户报告，详见[最终选择与交付](04-最终方案、候选选择与工程交付.md)；目前没有独立上传回执或原始平台评测记录，也没有获奖证据。

| 主要限制 | 当前证据能支持到哪里 |
|---|---|
| exact-v6 仅一个被接受的完整样本 | 支持一次观测，不能估计稳定性能或期望分数 |
| 运行契约存在遵循失败 | 完整通关不能替代执行正确性验证 |
| exact-v6 冻结包上传未获证明 | 用户报告的上传评分不证明该冻结 ZIP 被平台受理 |
| 隐藏测试迁移未知 | 本地 Dev 结果不能外推为 hidden Test 成绩 |
| 稳定高分与因果收益未知 | 不能声称某个 Skill 带来固定比例提升 |

这些限制是项目成果的一部分：复核者应同时看到有效结果和使结论不能继续外推的证据。

## 1. 赛题与环境

项目对应 2026 CCF BDCI【华为openJiuwen】Agent 职场长程生存与晋升挑战。参赛方案使用 JiuwenSwarm 和 Agent Skills，经 career-emulator 的 MCP（模型上下文协议）接口参与职业模拟。这里的 Agent 会提交改变状态的行动，后续决策依赖环境实际反馈。[官方来源锁](../project/OFFICIAL_SOURCE_LOCK.md)

公开手册描述了月度事件、季度 Energy 分配与主行动、半年绩效反馈和多维结局。Agent 需要持续适应已有选择造成的状态变化。某个动作在前期可行，不意味着在资源下降、目标变化或剩余窗口缩短后仍应重复。

开发区 Dev 提供可观察的实验环境；保密 Test 用于正式评测。部分机制与风险触发条件不公开，项目不能把事后读到的隐藏计数或本地分析结果当作参赛者当时可用的信息。报告中的规则陈述以来源锁的历史核验为准，没有据此声称当前门户开放提交。

这使赛题同时包含两类要求：一类是选择怎样的行动，另一类是让选择通过正确的工具、会话和参数真正执行。模型写出一段合理建议，并不能证明模拟器接受了动作；动作回执成功，也不能替代下一次新鲜观察。

## 2. 项目要解决的工程问题

### 长程计划需要持续更新

一段固定动作配方无法表达完整的 48 个月过程。项目关注当前目标缺口、公开进展、剩余机会窗口和资源约束之间的关系。计划要随着正式反馈和观察更新，又要避免在没有新证据时反复推翻刚完成的判断。

这里没有声称恢复了晋升隐藏公式。可确认的是：工程方案将可见反馈、目标和候选排序安排给同一个规划责任方，减少不同模块各自提出总体战略的冲突。

### 事实、规划与风险需要明确归属

状态摘要应回答“现在能确认什么”；规划应回答“接下来最值得做什么”；风险审核应回答“这个具体候选是否有直接相关的重大风险”。若三个问题混写在同一段长提示中，复核者难以判断行动建议到底来自公开事实、一般推测还是风险偏好。

项目用三个 Skill 表达这些责任，最终动作仍由单一 Agent 提交。这是职责设计，并非三名独立 Agent 投票。[技术架构](02-Agent技术方案与系统架构.md)

### 运行结果需要绑定到正确身份

Candidate（候选方案）、一次 Run（运行样本）、当前源码 checkout 和最终 ZIP 是不同对象。方案可以更新，历史样本却不能因此归给新版本。日志中的一个分数也可能来自旧会话，需要额外核对。

项目因此记录来源版本、运行会话、原始证据与交付工件身份，保留技术失败和异常归因结果。这样可以说明“这一局是谁跑的”和“最终包到底包含什么”，而不是仅展示一个脱离来源的成绩截图。

### 完整通关与遵循正确性分别判断

长程运行会遇到参数拒绝、上下文压缩、状态恢复和工具连接等问题。终局分数不能说明这些环节都正确；良好的日志格式也不能说明策略有效。项目在分数之外单独检查 Adherence（运行遵循），并把缺陷写入最终限制。

## 3. 最终技术方案

最终 Candidate 为 **candidate-v6-auditable-control-loop**。它由持续生效的 Instruction（执行指令）约束一个动作提交者，再由三个 Skill 支撑决策：

| Skill | 主要责任 | 关键边界 |
|---|---|---|
| structured-state-board | 整理当前局公开事实、来源与新鲜度 | 不制定总体策略；不能用旧摘要覆盖新观察 |
| rolling-planning | 围绕目标缺口、进展、公开资源趋势与剩余窗口提出候选 | 是唯一策略规划责任方；不自行提交动作 |
| risk-review | 检查当前候选的直接重大风险，必要时要求有限备选比较 | 不变成第二个总体规划器，也不取得动作权 |

预期循环是：**新鲜观察 → 状态整理 → 规划候选 → 候选风险门 → 单一合法动作 → 再次观察**。风险作为成长决策的约束，不能自动把所有普通成本都解释为应放弃机会的理由。

实际运行未完全遵守这套契约。因此，表格描述的是方案设计，不能读成已证明每一步稳定执行。架构责任、运行接口及审计方式见 [02](02-Agent技术方案与系统架构.md)；具体 Skill 教学见 [Track A](../tutorial/track-a-skill/01-从零理解Agent、Instruction与Skill.md)。

## 4. 已完成的代表性成果

### 从真实基线到可审计完整轨迹

最初的 no-op 基线得到 **26.95 / 18.86 / 19m / E / L3**，建立了真实环境与最小运行起点。最终方案的完整样本到达 48 个月，观测到 M6、M12、M18、M36、M48 晋升，最终职级 L6。[基线与代表性证据](../project/FINAL_EVIDENCE_REVIEW.md)

这些结果说明项目曾完成不同阶段的真实运行。它们不是单变量对照：架构、提示、候选和轨迹均存在差异，不能把两端数值计算成某个机制的因果提升，也不能用一次好结果替代稳定性证明。

### 形成职责清晰的 Agent 方案

项目将状态、策略和候选风险分别安排给三个责任模块，并保持一个动作提交者。这个方案便于检查输入从哪里来、谁决定排序、谁能否决候选、谁实际调用工具。

它提供了可解释的结构，不证明三个 Skill 是普遍最优拆分。后续曾尝试四 Skill 与其他路线，但这些探索没有改变冻结包身份。[研发演进](03-研发演进、实验与失败复盘.md)

### 建立结果与执行的双重审查

运行复核同时保存了完整终局和遵循失败。项目没有把完成 48 个月包装为所有协议通过，也没有把工具或 Provider 异常补造为候选策略得分。异常记录支持后续对会话来源、压缩恢复和审计配对进行检查。

这种做法展示了证据处理能力：复核范围、未知原因和未执行步骤会影响下一步决策。它没有提供严格统计试验意义上的效果估计。

### 冻结可追溯的交付身份

最终包从历史 exact-v6 来源构建，运行内容没有被当前较新的 checkout 替换。来源版本、成员清单和工件哈希由权威记录维护，离线材料检查与隔离工具层检查有明确范围。[交付详情](04-最终方案、候选选择与工程交付.md)

冻结意味着可以核对所选材料。S11 冻结时没有官方上传回执；赛后用户报告的官网综合评分见 04，但尚无独立平台记录核验其上传与云端执行细节。工程交付准备不能被表述成官方完成验收。

## 5. 项目展示的技术价值

| 能力方向 | 仓库可观察的工作 | 评价边界 |
|---|---|---|
| Agent 架构 | 单一执行权与状态、规划、风险分工 | 架构可解释，不等于最优性能证明 |
| Skill 工程 | 触发、输入、职责、禁止权限和恢复要求 | 文本契约不保证模型遵循 |
| 运行集成 | Runner、框架、MCP 与动作反馈链 | 本地证据不能替代云端评测 |
| 实验设计 | 冻结身份、有限验证、反例与停止条件 | 历史小样本不能给出因果结论 |
| 证据工程 | 运行来源、技术失败分类、取证与保留 | 摘要和哈希不能替代唯一原始来源 |
| 可复核交付 | 历史源恢复、包成员限制、离线核验 | 不是官方上传回执 |

作品集可以围绕这些已经发生的工程工作展开。岗位能力等级、个人独立贡献与比赛名次是额外声明，不能由仓库存在直接推出；可使用的表达与核验方式见 [05](05-答辩、作品集与证据边界.md)。

## 6. 仍未证明什么

项目没有证明最终方案稳定 75+，没有估计其长期分布，也没有证明某个 Skill 独立提高分数或生存率。当前选择是基于有限证据的工程冻结；完整候选比较与已接受理由集中在 [04](04-最终方案、候选选择与工程交付.md)。

Team/Swarm 保持 **DEFERRED / NOT_TESTED**，不能作为单 Agent 优于多 Agent 的对照。Reviewer、Memory 等研究各自停在具体部署或信号边界，不能归纳为这些机制普遍无效。

部分原始证据仍处于取证保留状态。报告将其中已接受的结论用于展示，不意味着可以删除原件或解除保留。项目仍在 S11 整理阶段；报告完成不等于整个 Stage 已宣布关闭。[当前状态](../project/CURRENT_STATE.md)
