# 00｜阅读导航

这组材料把 CareerSim BDCI26 项目整理成一条可供答辩、技术交流、作品集和面试使用的阅读路线。它面向第一次接触本仓库的人，先解释题目和系统，再说明架构如何工作、项目为何作出最终选择。

这不是新的工程事实源。工程事实仍以官方来源锁、提交身份、运行记录和审计为准；本目录负责用中文讲清这些事实，并把读者带回可复核的来源。发现冲突时，以对应的工程记录为准。

目前共有八篇报告，分成两个互补部分：00–03 解释比赛、系统架构和研发演进；04–07 分别讨论实验设计、失败与负结果、候选选择、工程实现和冻结交付。00 负责导航，01 交代比赛和项目对象，02 解释运行中的技术职责，03 重建研发判断；后四篇再按问题深入证据方法、失败分类、最终决策和交付链。答辩时如果被问到精确数值、日期、Skill 哈希或材料是否上传，摘要只是入口，应继续打开权威记录确认原始范围。

## 1. 这套材料是什么

仓库同时有两种阅读层次：

- 工程事实层记录精确身份、运行结果、代码与包哈希、限制及证据路径，适合实施、审计和复现。
- 人读材料层解释这些事实对项目意味着什么，适合快速了解、答辩准备和交流。

本组包含 00–07。它们不替代运行报告，不把设计意图改写为已验证的运行行为，也不删减工程层记录的未知项。

## 2. 推荐阅读路线

- **五分钟快速了解：**读本篇第 3 节，再看 [01｜赛题与项目总览](01-赛题与项目总览.md) 的题目、系统对象和最终结果。离开时至少记住三件事：模拟任务有长期状态；最终交付是一份固定身份的 ZIP；本地完整一局不等于平台结果。
- **技术路线：**从 01 了解模拟循环，再读 [02｜Agent 技术方案与系统架构](02-Agent技术方案与系统架构.md)，最后看 [03｜完整研发流程与方案演进](03-完整研发流程与方案演进.md) 的架构形成和验证边界。读 02 时优先看动作闭环与职责边界；读 03 时追问每次架构扩展实际解决了什么问题。
- **实验与复盘：**读 [04｜实验设计与证据评估](04-实验设计与证据评估.md) 了解证据层级，再读 [05｜失败路线与负结果复盘](05-失败路线与负结果复盘.md) 区分技术中断、自然终局、遵循失败和未测试路线。
- **答辩准备：**按 01 → 02 → 04 → 06 阅读。重点准备 Agent 怎样连续决策、为什么采用单一动作提交者、实验分别证明什么、最终为什么选择 exact v6。回答时先说可观察事实，再说工程解释，最后说明仍未知的部分。
- **简历与面试：**读 03 的研发演进、05 的失败复盘、06 的候选选择和 07 的交付边界，再对照工程证据索引，分别说明做过什么、观察到什么、仍不能下什么结论。不要把候选设计写成已部署功能，也不要把单局成绩说成稳定竞赛水平。
- **需要精确事实：**直接查 [最终身份](../project/FINAL_SUBMISSION_IDENTITY.json)、[最终打包记录](../project/FINAL_SUBMISSION_MANIFEST.md)、[运行与审计索引](../project/FINAL_EVIDENCE_REVIEW.md)。

本组覆盖 00–07；尚未创建的 08–10 不在导航中预留死链。

## 3. 项目结论速览

最终冻结的是历史 exact v6：Candidate 为 candidate-v6-auditable-control-loop，来源提交为 1114a04b75548cf52f030d123564e527060fc061，采用 Single Agent + 3 Skills。唯一冻结提交包为 FZU-Loss-final-v6.zip，包含 7 个文件，最终 SHA-256 为 31e836b591703dfe520916828da033a57de260bb451d97047bbaee9daaa11b9b。

这条路线有一个被接受的完整运行样本：75.29 quantitative score、52.70 competition partial score、48 个月、A、L6。该样本被记录为 RUNTIME_ADHERENCE_FAIL（运行契约遵循失败）。它能说明这一次完整轨迹发生了什么，不能说明稳定分数、策略因果收益或隐藏测试表现。Candidate v1 曾有 76.04 的单次结果；同一 Candidate 的另一局为 35.31、25 个月、D、L4。v8a 四 Skill Candidate 也有 72.65 和 59.00 两个完整样本。不同版本和少量样本不能组成受控比较。

冻结包完成了本地离线校验，但官方上传没有执行，也没有平台评测结果。当前 main checkout 保存的是历史 v8a 四 Skill 工程状态；它不等于 exact-v6 ZIP 的来源身份。

## 5. 事实与证据说明

报告会区分“观察到的事实”和“对事实的解释”。一次游戏中的分数、月份和动作属于该局观测；把结果归因于某个 Skill、动作或架构，是需要对照设计支撑的假设。只有多个样本也不自动构成统计结论，版本、环境和输入不一致时尤其如此。

读者可以用三个问题检查叙事是否越界：这是哪个 Candidate 和哪一次运行？记录的是观测、审计结论，还是对结果的推断？这项结论是否被限制在它实际覆盖的 Dev、版本和样本数范围内？如果其中一个问题没有答案，应暂时把结论当作未知，而不是从邻近章节补齐。

因此，75.29 被写作 exact v6 的一个完整样本，而不是稳定表现；v8a 的两个分数被写作同一候选的两条不同轨迹，而不是 exact v6 的复验。没有官方回执，就不能把本地 ZIP 冻结说成已经提交；没有隐藏集评测，就不声称对隐藏 Test 泛化。
