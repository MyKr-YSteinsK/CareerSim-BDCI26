# 00｜阅读导航

这组材料把 CareerSim BDCI26 项目整理成一条可供答辩、技术交流、作品集和面试使用的阅读路线。它面向第一次接触本仓库的人，先解释题目和系统，再说明架构如何工作、项目为何作出最终选择。

这不是新的工程事实源。工程事实仍以官方来源锁、提交身份、运行记录和审计为准；本目录负责用中文讲清这些事实，并把读者带回可复核的来源。发现冲突时，以对应的工程记录为准。

目前共有十一篇报告，分成两个互补部分：00–07 解释比赛、系统架构、实验、候选选择和工程交付；08–10 提供答辩准备、职业材料和证据索引。00 负责导航，01 交代比赛和项目对象，02 解释运行中的技术职责，03 重建研发判断；04–07 按问题深入证据方法、失败分类、最终决策和交付链。答辩时如果被问到精确数值、日期、Skill 哈希或材料是否上传，摘要只是入口，应继续打开权威记录确认原始范围。

## 1. 这套材料是什么

仓库同时有两种阅读层次：

- 工程事实层记录精确身份、运行结果、代码与包哈希、限制及证据路径，适合实施、审计和复现。
- 人读材料层解释这些事实对项目意味着什么，适合快速了解、答辩准备和交流。

本组包含 00–10。它们不替代运行报告，不把设计意图改写为已验证的运行行为，也不删减工程层记录的未知项。

## 5. 事实与证据说明

报告会区分“观察到的事实”和“对事实的解释”。一次游戏中的分数、月份和动作属于该局观测；把结果归因于某个 Skill、动作或架构，是需要对照设计支撑的假设。只有多个样本也不自动构成统计结论，版本、环境和输入不一致时尤其如此。

读者可以用三个问题检查叙事是否越界：这是哪个 Candidate 和哪一次运行？记录的是观测、审计结论，还是对结果的推断？这项结论是否被限制在它实际覆盖的 Dev、版本和样本数范围内？如果其中一个问题没有答案，应暂时把结论当作未知，而不是从邻近章节补齐。

因此，75.29 被写作 exact v6 的一个完整样本，而不是稳定表现；v8a 的两个分数被写作同一候选的两条不同轨迹，而不是 exact v6 的复验。没有官方回执，就不能把本地 ZIP 冻结说成已经提交；没有隐藏集评测，就不声称对隐藏 Test 泛化。
