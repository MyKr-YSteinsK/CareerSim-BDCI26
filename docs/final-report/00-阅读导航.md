# CareerSim｜最终报告阅读导航

本项目围绕 2026 CCF BDCI【华为openJiuwen】Agent 职场长程生存与晋升挑战，构建了以单一动作提交者、三个职责明确的 Skill 和运行证据审计支撑的长程决策方案，并冻结了可追溯的本地交付包。

这组六篇报告面向评委、技术面试官和作品集读者。它说明项目成果及限制；从零学习实现细节，请进入下方教程。运行分数是本地 Dev 观测；另有三份赛后官网综合评分为用户报告，见[04](04-最终方案、候选选择与工程交付.md)。两类分数来源和口径不同，不能互换。

## 按用途选择路径

- **比赛答辩：**01 建立项目定位 → 04 核对最终方案及限制 → 05 准备困难问答；技术追问回到 02、03。
- **技术面试：**01 → 02 → 03 → 04。优先观察职责边界、失败分类和交付身份是否一致。
- **作品集：**01 → 05 的素材与声明边界。使用个人贡献措辞前，核实本人实际承担的工作。
- **深入工程复核：**02、03、04 → 各篇所列权威来源。数值争议回逐局记录，包身份争议回提交身份与 manifest。

## 阅读时保留的三个区别

1. **设计与执行：**方案要求怎样做，不等于模型实际全部做到。最终样本有完整终局，也有运行契约遵循失败。
2. **运行与评测：**本地完成、包离线通过、冻结时上传状态、赛后官网评分是不同事件；官网综合评分为用户报告，尚无独立平台回执或原始评测记录，详见[04](04-最终方案、候选选择与工程交付.md)。
3. **仓库与工件：**当前工程 checkout 保留历史 v8a 状态，冻结包来自 exact-v6。不要把当前文件误认成最终包。

完整候选对比与包标识由 04 维护；运行缺陷也在该篇集中说明。05 提供对外表达约束，不另建分数或 hold 台账。
