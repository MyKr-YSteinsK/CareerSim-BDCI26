# 最终决策：保留原始 v6

## 选择与证据边界

我们最终选择 `candidate-v6-auditable-control-loop`。它使用 Single Agent 与 Board、Planning、Risk 三个 Skill，记录中的一次完整 Dev 对局达到 **75.29 / 48个月 / A / L6**，是我们已有成熟三 Skill 路线中观察到的最高分。

这是单样本的高上限证据，不是稳定性证明。该局出现过一次被工具拒绝的 Energy 多选参数、两次压缩后未按约定重读 Skill，以及动作控制标记无法完整对齐的问题。游戏自然完成与每个协议正确执行，是两项不同结论。此次提交接受这些已知不足，保留实际跑出该结果的运行指令和 Skill，不将后续修复当作同一版本。

## 三个问题塑造了职责划分

长期任务需要区分“当前事实是什么”和“接下来要做什么”。Board 因此只维护本局公开状态及可归因变化，Planning 才持有 Gap 与长程判断。时间相邻并不保证因果，混杂的变化留作 UNKNOWN，避免把宣传效果或过期反馈当作进展。

风险也不能成为每个步骤的默认目标。v6 的规则把 Risk 放在候选之后：普通工作代价先由 Planning 权衡，明确的重大风险再触发候选审核。实际高分局中，季度主行动14次申请关键项目、2次低调避险；它在承担成长任务的同时，仍保留对当前风险的响应空间。这个行动分布只是观察，不是提交中固定的配额。

重复推理和重复投资是另一项负担。原版把正式 Review、季度资源决策和上下文恢复作为较完整的 checkpoint，普通剧情只做有界比较。高分局也曾在汇报未带来新增 Output 后重新考虑其它 Energy 路线。我们保留这种依公开响应更新判断的机制，不从一局轨迹提取固定动作顺序。

## 最终保留的四个决定

**一个 Agent 提交动作。** 三个 Skill 都不能调用游戏动作；主 Agent 统一使用当前 session 和合法菜单。选择 Single Agent 的理由是保持同一状态与提交链，不是已经证明多 Agent 一定低效。Team/reviewer 路线没有建立可部署且机械只读的审查边界，不能拿来替换已完成完整对局的执行者。

**事实、规划、风险分别拥有自己的判断。** Board 不决定 Gap，Risk 不重新规划长期目标。Planning 借助公开反馈更新目标，Risk 只检查最终候选。这个分工让一次 warning 不必自动覆盖整个职业方向，也让重大约束仍能阻止会直接加重它的动作。

**在生存约束内继续成长。** Risk Budget 来自公开状态和趋势；安全没有被写成每一步都选最保守动作。v6 的41次 Energy 行动同时包含汇报15次、健康恢复10次、人脉8次、高强度工作5次及其它修复行动。我们从这个结果保留成长与修复可以并存的判断，不把次数改写成规则，也不声称某个动作造成了75.29。

**用新观察更新判断。** 该局202次成功状态改变之后，都在下一次成功动作前取得了 fresh observe。这支持原版的新鲜状态闭环确实被执行过。它没有证明压缩恢复也可靠：两次压缩后都未重读三份 Skill。因此新观察的执行证据与规则恢复的失败证据分别记录。

我们更早的四 Skill 路线曾有76.04高分，另一次在25个月以35.31信任终止。它不支持“更早版本都差”或“三个 Skill 天然最优”，只提醒我们同时看上限和失败下限。这次比较最终成熟路线，而不是只挑历史最大数字。

## 最后一次提交的取舍

只剩一次提交机会时，我们选择已有75.29和L6样本的 v6，承担更高的不确定性。v6d 的三局都生存到48个月，是重要的保守参照，但三局得分仍在59.67至71.67之间；这些样本不足以证明它具有更高的真实生存概率，也没有提供75+可达性样本。

保持原始运行字节，让提交方案与75.29证据对应。修复执行协议、合并后续规划或改写规则，即使看起来合理，也会形成没有这份运行证据的新策略。此次不做这种替换。文档说明设计和风险，不替 runtime 添加新指令。

本地 Dev 的结果不能数值外推到隐藏云端。此次选择观察到的高上限，真实期望表现和稳定75+仍然未知。
