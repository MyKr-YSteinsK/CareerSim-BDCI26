# 决策与实验记录

这个方案不是从一开始就定下来的。前面我们试过更激进的成长，也试过更重的保护，结果都暴露出明显问题。最终版本基本是从这些失败里一点点删出来的。

最早的 baseline 只有 26.95 分，19 个月就结束。之后我们做过一个历史高分版本，单局到了 76.04，但同一个 Candidate 第二次只有 35.31，而且 25 个月就终止。这件事对后面的影响很大：我们不再把“最高单局分”当成最终选择标准。

后面几个比较关键的完整运行是：

| 版本 | Quantitative | Survival | 结果 |
| --- | ---: | ---: | --- |
| v6 | 75.29 | 48m | A / L6 |
| v7o | 71.83 | 48m | A / L5 |
| v7t | 65.71 | 48m | B / L5 |
| v7v | 58.97 | 48m | C / L5 |
| v8a Run 1 | 72.65 | 48m | A / L5 |
| v8a Run 2 | 59.00 | 48m | C / L4 |

这些不是严格的随机对照实验，所以我们只把它们当作设计证据。比较下来，有几件事比较稳定。

第一，Skill、Network、Wealth 和 Level 的长期积累比“把 Health 永远补满”更像高分路径。高分样本里这些职业资本通常都持续增长，但这不代表某个单项有固定阈值。

第二，晋升很重要，但不能把晋升本身当成唯一目标。我们见过 M6、M12 都晋升，最后还是因为 trust 路径失败；也见过错过某次 Review 后继续恢复并拿到 70+。因此最终 Planning 保留 promotion-first 的 ambition，但真正执行时还是看当前 Review window 的公开成果和成长。

第三，过度保护会伤害长期成绩。早期一些版本只要 Health 下降就反复恢复，甚至进入很长的 Stabilize 区间。后来我们把它收紧成“只有 fresh public material threat 才 Stabilize”，处理完就回 Advance。

第四，NO_GAIN 不能被解释成隐藏 cap。我们在不同 Level、不同时间里看到过同类动作从没增长变成有增长，也看到相同选择在不同轨迹上得到不同公开响应。因此最终只做局部折价，不写隐藏公式，也不把 Dev 事件做成答案表。

为什么最终提交 v8a，而不是历史最高分的 v6 或最后静态改出来的 v9a？

v6 的单局成绩更高，但当时 runtime 还有明确的 adherence 问题，包括 Review trigger、context recovery 和旧式控制标记。v7o 的策略核心比较强，所以后来我们把它重新移植到更可靠的执行壳里，得到 v8a。v8a 有两次独立完整 48 月运行，分别 72.65 和 59.00，至少证明这套组合能完整跑完不同轨迹。

截止前我们还做了一个很小的 v9a 静态实验：当当前成长路径 fresh NO_GAIN、又没有已知有效替代项时，允许比较一次未测试的高价值成长方向。这个想法静态上合理，但没有真实对局验证，所以没有放进最终 submission。我们宁愿交一个真实跑过的版本，也不想在最后几分钟换成“看起来更聪明、实际上没跑过”的 Prompt。

当前版本仍有已知限制。Dev 两局的分数差异不小，说明事件路径和公开响应会带来明显方差；我们也不能证明 hidden Test 会复制 Dev 的分布。Risk / Delivery 的一些标记格式和证据纪律还有改进空间。因此这份提交的定位很明确：不是宣称找到了隐藏规则，而是提交一套已经完整跑过、边界清楚、能持续 48 个月工作的长程 Agent 控制方案。
