# Skill 设计：事实、规划与候选风险门

## 设计目标

CareerSim 的难点是把当前选择接到长期职业轨迹上。一次剧情可能改变健康或信任状况；季度只有有限 Energy；半年 Review 又要求之前的积累能够兑现。只看当步收益容易透支资源，始终避险又会失去成长机会。上下文越来越长时，旧状态和新回执还可能混在一起。

我们把这些判断拆成三个职责：先确认事实，再选择目标和动作，最后检查这个动作是否触碰当前重大风险。三个 Skill 都是主 Agent 使用的规则，不是三个独立 Agent。

## 一个提交者，三个职责

| Skill | 输入与输出 | 职责边界 |
|---|---|---|
| structured-state-board | 本局新鲜观察、公开反馈；输出相关事实、变化方向与来源 | 不给动作建议，不判定 Risk Budget |
| rolling-planning | Board、当前合法菜单与可实现时间窗；输出 Primary Gap、Progress、Risk Budget 和候选 | 不修改事实，不直接提交动作 |
| risk-review | 已生成的候选及直接相关公开事实；输出风险门结果与简短理由 | 不重新排序整局目标，不成为第二个规划者 |

主 Agent 统一持有当前游戏 session，读取 Skill 并调用 `observe`、`take_action`。这样不需要在多个 Agent 之间同步月份、候选或提交权限，也避免两条执行链对同一状态分别采取动作。Skill 的职责分离靠规则约束，不能当作已经由代码强制保证的权限隔离。

## Board：先把可确认的事实收拢

每次 fresh observe 后，Board 核对 game session、月份、Review 窗口，以及 Health、Dignity、Skill、Network、Output、Wealth、Level。最新正式反馈、晋升结果和明确 warning 保留来源与月份。普通步骤只突出变化、相关事实和未知信息，不反复抄写完整状态。

Board 只在新局、季度首个资源决策、正式反馈、重要状态变化或上下文恢复时替换完整快照。近期效果最多保留两条：同局、来源明确、没有中间事件污染的 before/after 才能直接比较；其它变化记 UNKNOWN。菜单宣传的收益、事情刚发生和事实已经兑现，是三种不同证据。

这一步把事实维护从策略判断中分开。Board 不会因为表扬就宣布目标完成，也不会因为某个数值下降就自行选择恢复。公开变化交给 Planning 判断其战略意义，候选的风险交给 Risk 判断。

## Planning：把当前动作接到 Review

Primary Gap（当前主要缺口）是当前最值得解决的一个公开问题；证据不足时保留 UNKNOWN。Planning 同时维护 Progress、Risk Budget 和收益仍能兑现的时间窗。它不是预先固定 48 个月的动作表，而是在正式反馈、晋升或未晋升后更新方向和比较基线。

Progress 只依据目标本身的公开进展。相同路径、相同目标在两个相邻且可比的 checkpoint 都没有增长，才诊断 STALLED；一次 flat 或来源混杂不能推出永久上限。诊断后比较一个不同类型的合法路径，是否切换仍取决于当前证据。

Risk Budget 是候选产生前对当前约束的判断。AVAILABLE 表示没有观察到正在收紧的重大生存约束，TIGHT 表示公开趋势正在限制可承担的代价，UNKNOWN 表示信息不足。健康持续下降，或其它生存相关维度持续恶化并伴随可信 warning，会影响这个判断；这里没有数值门槛或隐藏风险估计。TIGHT 限制的是会加重该约束的非必要成长，不是所有成长。

季度首次 Energy 决策把资源行动与季度主行动放在一起考虑：它们如何补当前 Gap，是否重复投资，近期实际响应是否还支持这条路。之后每次动作都必须取得新观察并重新扫描，旧方案不能直接授权剩余行动。临近已知 Review 时检查仍会经历的事件暴露和可达到的恢复机会；晚期投资也要考虑收益能否在剩余时间内兑现。

普通剧情只比较最多两个真正竞争的合法候选。没有新事实就不反复讨论；正式反馈和季度决策才承担较完整的战略更新。这个取舍保留长程方向，同时减少在稳定事实上的重复推理。

## Risk：审核候选，不接管目标

Planning 先生成候选，Risk 再检查候选直接相关的 Material Risk（重大风险）。明确的健康危机、保密授权问题、诚信隐瞒、重大可靠性事故等需要进一步审核。普通工作负荷、少量状态代价、日常分歧属于 Soft Cost（普通代价），本身不足以否决有公开成长价值的动作。

这种区分要结合当前状态。若 Planning 已因持续健康恶化把 Risk Budget 设为 TIGHT，下一笔小额健康代价就不能孤立地当作无关紧要。Risk 会检查它是否直接加重已有约束，而不会重新选择 Primary Gap。

没有相关重大风险时返回 PASS；需要完整审核时返回 ALLOW、WARN、RECONSIDER 或 UNKNOWN，并给出一句公开理由。RECONSIDER 要求比较一个直接相关的合法替代，不等于自动选择最保守选项；换了候选就重新审核。原版规则也允许在完成比较、公开证据支持时保留原项。证据缺失则保留 UNKNOWN，不虚构确定性。

## 一次决策如何结束，下一次如何开始

新局取得首个观察后、首个动作前读取三份 Skill。主 Agent 完成 Board 扫描、Planning 选择和最终 Risk gate，输出紧邻动作的 CTRL 记录，再提交当前候选。CTRL 简记事实新鲜度、Gap、Progress、风险结论和 checkpoint；发生 RECONSIDER 时还记录必要比较是否完成。

回执之后先 fresh observe，再进入下一次扫描。事实收集和策略选择不能靠上一动作的回执自行补成新状态。规则要求上下文恢复时先确认同一 session、重新观察、重读三个 Skill，再重建事实和规划。普通上下文不逐步重读完整文件。CTRL 和恢复要求都是执行协议，实际 adherence 的不足见决策文档；它们不是行为保证。

## 实现边界

只使用本局 participant-visible public evidence 和公开手册。不读取隐藏字段、内部事件效果或本机数据库，不猜晋升门槛，也没有事件标题到答案的映射。不建立文件型或跨局 Memory，不附加独立审查者；唯一动作提交者始终是主 Agent。长程状态留在当前对话中，因此上下文恢复是否执行，是这个实现必须承认的限制。
